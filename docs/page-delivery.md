# Page delivery and the starting point

The internal route prefix adopts the canonical shell/header/page composition. Existing product routes remain byte-frozen migration debt in `web/tests/page-migration.json`, each with its exact route, source hash and shared reason. They have **no six-method verdict**. The inventory also holds the old shell/header/navigation/preferences/provider bytes; seven comment-only shell hashes translate through the single exact main integration documented in the frontend rules. Later edits and forged hashes remain refused. The ordinary interface ledger separately shrinks as findings genuinely retire.

`/en/internal/page` and `/ar/internal/page` demonstrate the actual starting composition. The route is unlisted/noindex, not protected by obscurity. Its endpoint serves explicit invented review records only: no market answer, identity request, audited read or mutation. Long/mixed/Arabic/emoji, zero, one, page-boundary and 1,000-record bodies pass through the same read and twelve-record pagination. Refresh and retry use the real example endpoint through the existing bounded transport, including its invocation/body-read deadline and the query's abort signal. The note field is local and never sent, keyed by neither locale nor route filters.

## Source contracts, not measurement verdicts

| Method | Shared implementation | Internal component board | Page starting point | Runtime proof |
|---|---|---|---|---|
| Ready before press | Full `router.prefetch` plus full native Link prefetch until the lazy controller owns glance warming | Registered full destination | Registered full destination | Owed: full code/server payload, not just loading boundary; no destination request at press |
| Reads on intent | One definition/key/call for the mounted read and warm; resting pointer, focus, primary press/touch and visible idle batches | No server reads: local examples | Same `demoRead` as mounted view | Owed: real delayed-network trace |
| Retained answers | One in-memory adoption cache, 30s fresh/30min inactive hold; identity/access purge cancels and fences late answers | Local examples, no server cache | Scoped answer survives route excursions | Owed: browser revisit/access matrix |
| Refresh behind content | Active stale reads refresh on committed view changes; previous filter answer only while its exact live-scope query remains held | No server reads | Existing data remains, including failed refresh | Owed: stale/six-minute revisit with successful fresh read |
| First-answer placeholder only | Branch on absence of data, not background activity | No asynchronous page data | Empty answers are real answers, not loading | Owed: rendered placeholder frames |
| One short arrival | Shared opacity recipe, once per view/access, never refresh/filter/revisit or keyboard replay | Existing accepted board behavior | `AnswerArrival` claims the first shown answer | Owed: actual frames/interruption/reduced motion |

`web/lib/page-speed/pages.json` is the exact adoption table and content locator. Its proof field remains `owed`; source presence cannot change that. New pages cannot use an `own`/unclassified read policy. Unknown, external, financial, action and API routes are not warming destinations. Full-prefetch dispatch is a request, **not a readiness signal**. Page request renewal while visible asks only code/server payload, never destination reads; hidden tabs stop new idle/intent work. Observers/listeners/tasks are disposed on exit. If glance observers are unavailable, native full Link prefetch stays on.

Page consumers import only the neutral `definition`, client `read`/`arrival`, and same-document `address` helpers. Private cache/provider/controller parts belong only to named integration owners; another file in the same directory cannot create a second read or warming family. The contract check covers aliases, relative/private index spellings and literal dynamic imports/re-exports, while still requiring line-by-line review for arbitrary data flow.

The existing product QueryClient, freshness/retention settings, access clearing, session protocol and language-switch path remain unchanged. The adoption cache is a separate memory-only scope, not another policy for old pages. No new language switch exists. Identity/access replaces the scope; locale and route do not remount editable children. Navigation visibility uses existing roles and never replaces server authorization.

## Page-size ratchet

The comparison reads Next's emitted first-load JavaScript chunk diagnostics, resolves/de-duplicates real files, rejects missing/escaping/symbolic-outside chunks and measures gzip level9 bytes. Every built route participates, including old routes whose imports changed. One-byte growth fails. A new page needs approval for its whole first-load size; deletion is not silently used as credit elsewhere.

Measurements are **not part of quick checks**. When production measurement is permitted, on the authorized machine and a clean committed checkout:

```
pnpm --filter beirut-time-web size:measure --allow-build --out /absolute/path/head-sizes.json
pnpm --filter beirut-time-web size:compare --base /absolute/path/base-sizes.json --head /absolute/path/head-sizes.json
```

Measure the base on the same machine by the same command in its authorized checkout. The command runs that checkout's build itself, checks unchanged source before/after, and records commit/tree/build identity; it never labels an old build with today's commit. Output belongs outside the source checkout. The comparison cannot launch a build.

If measured growth is explicitly approved, add exactly one `web/perf/approvals/*.json` file with `baseCommit`, `reason` and `pages` mapping exact routes to positive maximum growth bytes. The head identity is taken from that committed addition, not a self-referential hash inside the file. It must belong to that exact comparison and be added by it; earlier approvals cannot be reused, edited, deleted or renamed. The Git lookup anchors this directory at the repository top even when the command runs from `web/`, and reads the approval from the exact committed head rather than the working file. No size approval or measurement has been invented for this foundation.

Quick Node tests use only tiny synthetic emitted files. Lint/types/source checks and focused cache/controller/SSR units do not prove production chunk separation, actual first-load size, hydration, browser paint or navigation speed. All those proofs, real-phone and assistive checks remain **owed**.
