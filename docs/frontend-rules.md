# Beirut Time frontend rules

These rules govern the marketplace in English and Arabic, light and dark, on a computer and a phone. A static pass proves only the patterns it measures, not that a page looks or works correctly. Each change also receives a line-by-line review against every applicable row below. A rule marked **Review** requires the named review step; it is not an unimplemented automatic guarantee.

## Checks and the migration boundary

From the repository root, with the pinned package manager:

- `pnpm --filter beirut-time-web lint` runs exactly `cd .. && web/node_modules/.bin/eslint --config web/eslint.config.mjs web packages/ui/src --max-warnings 0` from `web/`. Both application and shared components are included; one warning fails.
- `pnpm --filter beirut-time-web typecheck` checks application and imported shared component types.
- `pnpm --filter beirut-time-web ui:rules` checks production CSS and script in `web/` and `packages/ui/src/`, including shell, features and libraries, then the page/delivery/migration contract.
- `pnpm --filter beirut-time-web test:ui-rules` tests the checker, lint threshold, rulebook coverage and worst-case fixtures only.

`web/tests/ui-rules-baseline.json` records Sprint 1 debt by exact file, rule count and SHA-256 of its bytes. Unchanged files may not increase their recorded counts. **New or changed production files must have zero findings**, even when an old violation is on an unchanged line. A file cannot borrow another file's allowance. When a count falls, lower the ledger in that change; do not refresh its hash. The first committed ledger is the immutable provenance ceiling. Every later proposal is also compared with the latest accepted ledger at HEAD: removed files/checks cannot return, lowered counts cannot rise again, and hashes cannot change. A committed deletion leaves an empty ceiling; reintroducing the old ledger does not reset it. Before the first commit, every entry must be re-derived from main's exact source bytes under the proposed check policy. There is no update-baseline command. `ui:rules --strict` disallows all debt. `--report` prints findings without changing files.

Existing Sprint 1 pages retain their rendering during the foundation work. The root default tab titles alone now read `Time well chosen · Beirut Time` and `للوقت حُسن الاختيار · بيروت تايم`, keeping the same words in the required order; this intentionally corrects the inherited home-page title. Its three fixed root findings retire from the active ledger (91 files/321 findings); the first committed 92-file/324-finding provenance and every surviving hash/count stay unchanged. Compatibility aliases point into the same tokens and recipes; they are not a second design system. Debt is not a release waiver. Page rebuilds remove it rather than expand the ledger.

`@beirut-time/ui/foundation` is the sole canonical component entry. The existing package root and shell re-export serve only unchanged Sprint 1 callers; their implementations and old styles are frozen by `web/tests/legacy-ui-sources.json`. These are the original main bytes, including the preceding reviewed comment-only image lint boundary, not permission for a new legacy implementation. Every new or changed file imports canonical controls from the foundation entry, never their root counterparts, aliases, namespace imports or dynamic root loads. The import gate admits only the root, the two declared motion readers and this exact foundation subpath, not arbitrary private paths. Each legacy root implementation and its export are deleted when its final Sprint 1 consumer is rebuilt. The canonical State announces errors; the old root State's missing error alert stays exactly one recorded finding until its callers rebuild. It is not described as fixed by adding a correct canonical State.

`web/styles/bt-motion.css` is the one canonical owner for new duration/curve tokens, keyframes, motion recipes and reduced-motion handling. `web/styles/motion.css` is a frozen compatibility sheet, accepted only at SHA-256 `020d59936efcd46cfc0c76ccc41cb64684f94721e7ba9065035e6c789614ae43`. It is never extended or retuned. An edit to it fails; deleting it requires removing its import and every remaining legacy consumer. New or changed CSS/script files may not name its keyframes/classes, including shared class-recipe strings. Only exact unchanged HEAD bytes retain existing consumers; a copied file at another path or restored old consumer after a rebuild receives no allowance. The frozen sheet is deleted when the last Sprint 1 consumer is rebuilt.

Review steps used below:

- **Content review**: feed the shared fixture through real props or mocked responses; inspect 1440, 390, 360 and 320px, the component's actual narrow container, 200% text, RTL, both languages and themes. Try empty, one, page-size, page-size-plus-one and 1,000-row collections. Check every value and control, not just the first row.
- **Visual review**: compare stable geometry and every control state on the drawing board and affected pages; record intentional differences. Review colour contrast independently of the screenshot.
- **Motion review**: first decide frequency and purpose, then implement, then review the finished motion. Explicitly apply find-animation-opportunities, animate, review-animations, improve-animations, remove-animations and animation-performance where relevant. Inspect interruption, slow playback, reduced motion and input modality. Keep a before/after record and a one-step revert.
- **Gesture review**: exercise distance, flick, reversal, re-grab, nested scrolling, nested surfaces and focus restoration on each shared primitive; record real-phone evidence separately.
- **Keyboard review**: Tab and Shift-Tab reach every action, Enter/Space activate it, Escape closes layers, focus is visible, unobscured and restored. Check screen-reader announcements and WCAG 2.2 AA, including 4.5:1 ordinary text and 3:1 focus/non-text contrast.
- **Reuse review**: search all pages for the old recipe whenever its shared version changes. A repeated recipe moves into one shared piece, with no local opt-out. Each newly approved design is recorded as a rule here and swept across every applicable page in the same program, not only across repeated-recipe consumers. An approved drawing-board composition is imported into the page, not recreated.
- **Delivery review**: inspect imports and the page-size comparison; exercise first load, warm navigation, stale revisit and identity/access changes. Heavy measurement remains a separate proof, not inferred from source.

## What the automatic checker cannot see

The checker guards against drift; it does not certify a design or all runtime behavior. It cannot prove the final cascade, contrast, runtime content or arbitrary cross-module behavior. Indirection it cannot read at recognized guarded styling or animation sites is reported as `bt-style-opaque` for review, not certified. Mutable bindings, referenced containers, unknown spreads and shadowed shared imports are deliberately conservative findings, not a full data-flow analysis. The line-by-line review of every slice remains the main control, alongside the manual checks and deferred runtime proofs below.

### Number contract (BT-UI-06)

The foundation entry exports `numberFormatter`, `formatNumber`, `formatCount` and `formatAmount`. Arabic always passes `numberingSystem: 'arab'`; English always passes `numberingSystem: 'latn'`. Number, currency, percentage, compact and any future date/time part formatter use that explicit choice, never the host's locale default. Plural categories follow the reader's locale; decimal money strings preserve their exact value rather than round through a floating-point number. Codes, identifiers, references, URLs and machine-readable values are never reformatted. Frozen Sprint 1 formatters remain unchanged until their pages adopt the shared helper. Focused tests assert both languages' exact parts, negative/zero/one/large/decimal/currency cases and independence from a host choosing the opposite default.

## Token and cascade contract

`web/app/globals.css` remains the sole ordered global entry: tokens, document base, motion, shared controls, shell, then page composition and phone adaptation. Shared component recipes have zero specificity in the components layer; named composition classes outrank those recipes; utilities outrank that layer. Do not add unlayered page rules to defeat this order. Tailwind @theme declarations stay top-level and unlayered. Feature code consumes global tokens; it never defines a private global palette, type scale or motion ladder. Only a shared accessibility or phone floor may be unlayered, with its override mechanism documented beside it.

`web/styles/tokens.css` owns visual primitive values, semantic light/dark roles, scales and compatibility aliases. The sole new pacing/keyframe/recipe owner is `web/styles/bt-motion.css`; its duration and curve properties are `--bt-motion-*` and `--bt-ease-*`. A surface and its ink are a pair: `background/foreground`, `card/card-foreground`, `popover/popover-foreground`, `primary/primary-foreground`, `muted/muted-foreground`. Coloured text uses readable ink roles, not a dark fill token. Fonts are local Latin and Arabic faces. Layout uses logical inline/block properties; isolate LTR watch references and money where necessary rather than reversing the whole shell. Arabic is a layout direction, not a separate page tree.

The foundation extends tokens in Beirut Time's vocabulary (`--bt-*` and `bt-*` recipes). Existing semantic roles and old aliases remain bridges until their last Sprint 1 consumer is rebuilt. Never add a new consumer of a legacy-only name. New motion durations, custom curves and shared keyframes/recipes live together in `web/styles/bt-motion.css`; script reads those CSS values at the action instead of holding a duplicate runtime table. Twenty exact pre-existing timing/curve declarations remain in their original root/theme contexts in `web/styles/tokens.css` only for compatibility; the owner check rejects additions or retuning there. Per-part reduced-motion kept properties are the narrow floor contract, not another duration ladder.

The layer ladder, owned in the token file, is: local decoration/content < pinned page chrome < navigation/dock < shade < dialog/sheet < nested popover/menu < toast < emergency loading surface < skip link. The registered names are `--bt-layer-content`, `--bt-layer-pinned`, `--bt-layer-navigation`, `--bt-layer-shade`, `--bt-layer-window`, `--bt-layer-menu`, `--bt-layer-toast`, `--bt-layer-loading` and `--bt-layer-skip`. Only `web/styles/tokens.css` may define them. A reference passes only after its name is actually declared there; numeric fallbacks and consumer-owned definitions fail. Existing declared `--z-avatar`, `--z-loading-overlay` and `--z-skip-link` are narrow migration aliases. Local zero/one layers are still named when they interoperate with shared surfaces. A component's stacking context is part of its contract; a number alone does not prove it draws over another context.

### Narrow cascade contracts

These are shared-floor contracts to implement in the foundation, not per-page permissions: `--bt-phone-hit-floor: 0px` only when the control draws its own 44px hit area; `--bt-phone-hit-floor: max-content` only when its words need intrinsic width and it supplies its own 44px height. Reduced motion reads separately registered, non-inheriting `--bt-motion-kept-animation`, `--bt-motion-kept-transition` and `--bt-motion-kept-iterations`, so a named part keeps only its documented gentle change and descendants do not inherit an exemption. `--bt-flat-ground` supplies an explicit token-derived solid ground to the no-glass fallback before a dark ground is painted. Each floor reads exactly its own property; none permits important declarations or unrelated overrides.

Frozen shared full-screen layer exceptions remain confined to `web/styles/ui.css`, `packages/ui/src/dialog.tsx` and `packages/ui/src/sheet.tsx`. New modal coverage is allowed only in `web/styles/bt-components.css`, in the components layer and exactly the `:where(.bt-surface-stage)` or `:where(.bt-surface-shade)` selector. These two shared hosts alone cover the viewport for focus-managed Dialog/Sheet composition; another file, selector union, wrapper or private host gets no allowance. Selected-thumb paint is confined to `packages/ui/src/segmented.tsx` and `packages/ui/src/segmented-thumb.tsx`. Merely placing another file in the shared package grants neither exception. The existing image delivery boundary alone may forward its native `img` rest parameter in `packages/ui/src/image-frame.tsx`; this does not exempt caller spreads, other tags, other files or opaque style/animation expressions from review.

### Named allowances

`web/app/layout.tsx` alone may compose its html font classes as `[lexendDeca.variable, arabic.variable].join(' ')` without an opaque-class finding. `ui-bootstrap.mjs` validates the two exact same-file local-font declarations and their import, and rejects another object, an alias/write/extra reference, extra class composition, a changed font configuration or a copied file. This is one compiler-generated class expression, not a root-file exemption. The old template-expression spelling retains its historical provenance finding. The corrected titles have no allowance.

The only frozen motion allowance is the exact compatibility-sheet hash above and the twenty fixed pre-existing timing declarations in the visual token owner. It grants no new consumer, class, keyframe, duration or curve. The canonical fold's `grid-template-rows` transition is confined to `web/styles/bt-motion.css`'s shared `.bt-fold` 0fr/1fr recipe; its inner box clips only collapsed content. Every other allowance must specify **one file, one gate, one selector/declaration shape and one reason**, be listed here and tested for rejection in another file and for a broader shape. Unknown or unresolvable duration tokens fail closed. Long motion tokens retain exact names and reasons below; they are not permission for a long menu transition. ### Shared recipe inventory

The following are shared work, not independent page solutions: folding sections, pressed feedback, reduced-motion handling, avatar initials, number/plural formatting, decoded image frames, skeleton rows, state faces, segmented thumbs, overlay/shade timing, drag dismissal, toast focus/reach, page headers, first-frame geometry and data-read/warming policy. Before adding a recipe, search these areas and all feature consumers. At the second use, extract the first use too. No per-page switch suppresses a shared correction.

## Speed and proof boundary

Every page eventually has an explicit entry proving six methods: code and the full destination server page payload ready before press (not merely the loading boundary), first reads ready on intent, access-partitioned data retained between visits, stale content kept while refreshing, placeholders only when no answer exists, and one short arrival fade without replay/stutter. Permission changes clear retained answers immediately. Warming never performs a mutation or an audited read. The new-page template will include this contract instead of asking a page owner to rediscover it.
