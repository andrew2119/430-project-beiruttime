# Protected purchase and business proof preparation

This is a synthetic contract harness, not connected acceptance. The 64 named journey entries are an explicit candidate coverage inventory, not a claim of 64 completed features. Each has positive, denied, stale, cross-account, cross-business, timeout, lost-response, duplicate, restart and recovery obligations. Their exact deferred records are generated in memory by `tests/integration/sprint-2/proof.py`; no result files are written into the repository.

Run the bounded local checks with:

```sh
/opt/bt/bin/python -m unittest discover -s tests/integration/sprint-2 -p 'test_*.py' -v
/opt/bt/bin/python tests/integration/sprint-2/proof.py
```

The versioned schema and deterministic freeze fixtures publish the local request shapes. `frozen_provider.py` executes private proxy competition, quote validation/commit/retention, durable payment notices and current job-authorization expectations with a restartable in-memory receipt store. The manifest publishes operation lookup, negative/recovery expectations, protected-route assertions and the display matrix. The versioned envelope validator rejects extra fields so restricted evidence cannot be accidentally copied into an envelope. Deterministic response examples are synthetic and contain no paid funds, accepted bid, winner, inspection pass, custody receipt, completed work or release. A response marked success means only an envelope example.

The ordered observation checker accepts caller-supplied observations and validates their shape, scope and unresolved prerequisites. Its source label is not provenance or signature verification. It always leaves connected acceptance deferred, even for a valid sequence. It cannot establish current authority, independent staffing, custody, signature validity, persistence, money or absence of duplicate effects. Those facts must be asserted against actual producer operations and the single Orders journal on the separate authorized machine.
