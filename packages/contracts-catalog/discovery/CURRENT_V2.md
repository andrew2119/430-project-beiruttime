# Public discovery v2

Public read operation lookup: `GET /v1/discovery/watches`, `GET /v1/discovery/watches/{id}`, and `GET /v1/discovery/watches/{id}/auction`. These reads never authorize a commitment.

Search links carry typed `min_price` and `max_price` in US dollars. The adapter converts exact decimal dollars to integer `min_minor` and `max_minor`; it converts old cents links exactly to their dollar equivalent. Only USD is active. Invalid ranges fail before a read. Cursors bind all applied criteria and expire after one day. Changing criteria restarts pagination.

Detail adds `no_documents`, sourced from the published listing declaration. Missing or conflicting declarations fail validation. Seller history and inspection results remain unavailable until their owning public provider supplies a current watch-bound response. Publication alone is no inspection result. Business onboarding is separate from watch inspection.

Public seller facts read: `GET /v1/public/sellers/{seller_id}/facts?watch_id={watch_id}&listing_revision={revision}`. The closed response binds schema_version `catalog-public-facts.v1`, seller_id, organization_id, watch_id, listing_revision, revision, city, released_sales, joined_at, review_distribution (five nonnegative counts), history (privacy-safe dated summaries), and inspection (`passed`, `failed`, `inconclusive`, or null). Counts include only released completed transactions. No identity proof, former owner or private evidence field is permitted. Identity owns this composed public response; absent wiring stays unavailable. Denied, stale, wrong-seller, wrong-watch, malformed, timeout and lost responses never supply facts. Repeated reads are safe; there is no command receipt or write retry.

Fixtures are development responses, never acceptance of a sale, inspection, payment or custody. Connected provider verification remains owed.

Search totals read: Orders supplies `GET /v1/public/listing-search-total` using the normalized filter fields and their criteria fingerprint. The response `{schema_version:"catalog-public-total.v1",criteria,total,revision,as_of}` counts available published matching stock across all pages, not just one window. A total older than 15 seconds, future-dated, denied or absent remains null and is labeled unavailable. A count is never purchase authority. This optional composed read requires the owning provider before connected acceptance.

Seller profile `/watches/{id}/seller` is scoped by a currently public watch. Its city comes only from the permitted seller facts, never inferred from watch location. `GET /v1/discovery/watches?seller_id={id}` uses the same current availability composition and criteria-bound pagination as browse. Seller identity in detail binds this query; unavailable membership facts do not grant any private access.

Read errors: `invalid_filters`, `invalid_range`, and `invalid_cursor` use 422; missing public stock uses 404; current ineligible business scope uses 403; unavailable dependencies and bounded search-window exhaustion use 503. A failed or uncertain read offers retry, never a successful command. Revisions are required positive integers; mismatched listing/business/watch bindings discard the response. Independent slot owners retain all command permission, pending-operation and retry behavior.

History pagination: the facts response requires `history_next_cursor` (null only at the end). `history` is one page of at most 100 entries, never a lifetime cap. The same scoped facts read accepts `cursor` and `revision`; its opaque cursor binds seller, organization, watch, listing revision, facts revision and position in an immutable ordered history snapshot. A changed scope, expired cursor or revision is refused, never restarted silently. Repeating a cursor returns the identical page. A continuation cursor advances and never repeats its input. These are provider obligations; connected verification remains owed.

Catalog exposes `GET /v1/discovery/watches/{id}/history?listing_revision=...&revision=...&cursor=...`. It rechecks public listing visibility and current business eligibility on every page, binds both revisions and returns `{history,next_cursor,revision,listing_revision}`. Missing, denied, stale, timeout and lost responses show unavailable with retry and a first-page action. The consumer never combines a failed page with a different snapshot. Changing the detail revision remounts only the history window.

History entries require `summary_en` and `summary_ar` for system descriptions. Both languages describe the same recorded fact; a missing translation rejects the response. Optional privacy-safe `user_note` contains user-written text and is displayed verbatim in either language. These fields apply to the initial history and every continuation page.
