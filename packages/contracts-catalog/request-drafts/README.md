# Private request drafts V1

`GET/POST /v1/request-drafts`, `GET/PATCH /v1/request-drafts/{id}`. Current buyer bearer identity, owner-private SQL scope. Commands require `Idempotency-Key`; PATCH requires `expected_revision`. `DraftInput`/`DraftUpdate` are the exact schemas. Optional brand and five option IDs are neutral **intent only**, never asserted compatibility or approval. Optional paired `configuration_id` / `configuration_revision` bind the released L10 private configuration: the server rereads `/v1/brand-options/configurations/{id}?expected_revision=N` with the same buyer credential, binds brand/base/caliber and exact selection/component/revision tuples, and stores only attached selection references, never the top-level uploaded inventory. The stored snapshot is not echoed in list previews and never implies assessment. Conflicting bare option IDs cannot replace a bound source choice. No evidence files, financial data, private identity records or client-supplied readiness are accepted. Before a full locale navigation, the screen acknowledges dirty neutral intent through this real save API and reopens the owner-scoped draft reference. Notes and credentials never enter browser storage or URLs; a failed save blocks that navigation with honest retry.

`GET /v1/request-drafts/{id}/readiness` composes actual brand, option and technical-intake reads. Unavailable upstream sections remain unavailable; durable owner drafts still reopen. Quote/consent/work/quality/collection are unavailable unless their released authoritative facts exist; no sample progression.

`POST /v1/request-drafts/{id}/actions/{action}` explicitly denies submit, approve, pay, start, complete and collect in Sprint 1. A saved draft is never an accepted job, quote or approval.

Released Directory V1 integration: `/v1/request-draft-catalogue?purpose=customization|servicing&after=<uuid>` reads Service Operations `/v1/directory/businesses?purpose=...&limit=20&after=...`, validates the business/capability/sample/revision fields and retains `next_after`, including empty filtered pages. Readiness rereads `/v1/directory/businesses/{brand_id}` for the draft's purpose; the servicing-only `/providers/{id}` eligibility projection cannot establish customization. The screen paginates actual public businesses. A buyer-safe request-bound technical-intake readiness read is still required: private staff-only `/v1/intake/records` is not a buyer draft projection. Until a provider releases that projection, intake stays explicitly unavailable with no speculative private-record request. Missing or denied data is never inferred as intake; Catalog's same-process options read by HTTP `/v1/brand-options/brands/{brand_id}`. `GET /v1/request-draft-configurations/{id}?revision=N` returns a safe owner-scoped configuration intent projection without private reference inventory. Each is isolated by a bounded dependency client. Provider contract integration replaces only these adapters, never reads another module's tables. Missing/invalid upstream states do not block neutral draft persistence and cannot authorize execution.

Events `catalog.request-draft-saved.v1` contain resource/revision only, transactional outbox to communications; notes and watch details remain private. The owning Catalog runtime configures service delivery credentials. Missing signing key leaves durable pending events.
