# Private consent v1

`GET /v1/consents` returns the current buyer's records only (maximum 50). `POST /v1/consents` takes request_id, brand_id, request_revision, purpose `brand-request-identity`, policy_version `demo-identity-v1`, decision `agree|refuse`, and bounded synthetic `DEMO:` evidence only when agreeing. Idempotency-Key is required. Evidence bytes, names and public URLs never appear in DTOs/events. No consent is an identity pass, payment-capacity attestation or business approval.

Before recording, Eligibility consumes the published Catalog request-drafts.v1 owner-private `GET /v1/request-drafts/{request_id}` with the buyer's Bearer token. Catalog authorizes that exact buyer; no client-supplied buyer id is accepted. The projected `id`, `brand_id`, `revision`, `kind=customization` and `status=draft` must match. Neutral notes/options are not retained. Eligibility then reads Identity businesses.v1 `GET /v1/businesses/{brand_id}` and requires the exact active platform-onboarded authenticated brand with customization capability. A neutral draft choice alone cannot assert official onboarding. The consent binds that immutable request revision; later grants must check it again. A dependency outage, owner denial, revoked business or unrecognized contract denies the write without evidence storage. Fixtures exist in tests only; production never fabricates request ownership or business assurance.

`POST /v1/consents/{id}/withdraw` takes expected_revision and Idempotency-Key. An active record becomes withdrawal_pending, increments revision and becomes locally ineffective immediately. Durable `eligibility.consent-withdrawal-requested.v1` envelopes go to Catalog and Orders with consent_id/buyer_id/brand_id/request_id/request_revision/revision/status, no evidence. Each consumer fences production and emits its own authenticated `catalog.consent-fenced.v1` or `orders.consent-fenced.v1` with consent_id and revision. After both current acknowledgements the state is withdrawn. Missing consumers keep the visible fence pending, never claim completed withdrawal. Refused/withdrawn/pending records cannot issue effective grants. Correction uses a new request revision and explicit fresh consent.

Evidence retrieval is a non-public API. Only a currently assigned reviewer with `eligibility.identity.review`, not the buyer themselves, can read bytes. Denials are audited without byte logging. Service event ingestion requires RS256 type=service, exact producer and Eligibility audience; public buyer access tokens cannot acknowledge a fence.
