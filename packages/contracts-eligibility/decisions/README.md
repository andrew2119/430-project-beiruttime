# Eligibility v1

Private commands: `POST /v1/eligibility-decisions`; durable lookup: `GET /v1/eligibility-decisions/operations/{operation_id}`. Reads and retries require current identity, business and case permission. Operation identifiers are scoped to their actor and consent. Reusing one with different bytes conflicts. A receipt reports historical outcome, never current permission to execute.

`v1.py` is the strict schema. The current-context provider must authenticate the consumer, authorize the exact actor/case/business, bind current request, watch commitment, accepted retained quote, consent, independent assignment and objective synthetic source facts. It supplies authoritative UTC time and a permission expiry independent of retained price expiry. No payment or wealth predicate participates. Missing, malformed, denied or timed-out providers cannot create a grant. Calls have a 1.2-second bound. The runtime composition steward must supply `eligibility_current(consent_id, actor_id, authorization)` returning this exact schema. No provider is installed by this module.

Reviews preserve correction and verdict history separately. Reason is a short decision explanation, never raw private evidence. Only the assigned independent reviewer may review; buyer and same-case brand approver cannot. Prepare and consume require their respective scoped permissions and current matching review. Approval and execution consume distinct single-use grants. Current identity, organization, assignment, policy, consent, request, watch, quote and review must still match. At expiry equality a grant is ineffective. Quote retention does not extend permission.

The local consent row is the serialization fence for withdrawal, review and grant commands. Withdrawal makes all grants ineffective immediately. Both request and order acknowledgement receipts are required for final withdrawal. Producers must serialize material invalidation and authority revocation with consumption before connected acceptance; a cached context is insufficient. Runtime registration, provider serialization and connected database/restart proofs remain required.

Responses use `eligibility-result.v1`, operation/subject/watch/actor/organization identifiers, expected revision, current revision, state, pending reason, next actor and next review time. A missing current provider returns an unavailable 503 without case identifiers or a receipt. Pending is retryable with the same operation identifier and does not create a terminal receipt. Denied/stale results are terminal receipts; a corrected action needs a new identifier. Public summaries contain only state, reason code and bound revisions, never source facts, evidence references or review explanation.
