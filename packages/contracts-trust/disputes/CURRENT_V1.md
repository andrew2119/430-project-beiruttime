# Private disputes v1

Composition supplies authenticated current identity and Orders adapters; this leaf registers no runtime. No local source snapshot grants authority.

Commands: `POST /v1/disputes/commands`. Lookup: `GET /v1/disputes/operations/{operation_id}?subject_id=…`. Private case: `GET /v1/disputes/{subject_id}`. All require current identity, selected organization, party scope or independent current assignment. Maximum body 40 KB, five protected references, five MB per file and fifteen MB total. Evidence provider checks current scope, checksum, size and media type; references and reasons never enter events, logs or previews.

The injected current-source read must revalidate identity, organization, record permission, buyer/seller, assignment revision and independence on every command, lookup and private read. It returns actual approved receipt, canonical watch commitment, retained quote/policy, principal, fees, immutable recipient, payment revision and current incident/dispute facts from authoritative producers. Private watches require actual inspection pass; business sales and jobs require actual assurance/quality. A dispatch scan is not receipt.

Opening is strictly before actual receipt plus 72 hours for inspected private sales or 168 hours for business sales/jobs. Equality closes. One case per order survives duplicates. No claimed protection until Orders confirms a hold. Resolution is independent, reasoned and assignment-bound; seller response is retained. Refund reserves principal only in the one Orders journal, counting unresolved and confirmed refunds together. Full job principal is refundable without subtracting the business fee; fee collection is a separate Orders responsibility. Release means resolving this dispute hold only: Orders must independently enforce all release prerequisites and any other incident hold.

Financial adapter `apply(binding)` is idempotent on `financial_operation_id`. Binding includes command digest, actor/organization, source and assignment revisions, watch, retained quote/policy, receipt/deadline, payment revision, immutable recipient, principal and fees. It atomically checks current facts and payout races, reserves refunds and records its inbox receipt. It returns the identical binding digest with `confirmed`, `pending` or `denied`; unknown/malformed/mismatched responses remain pending. A confirmed hold must still exist when processing later resolution. No provider response can redirect a recipient.

The local transaction atomically persists case and immutable operation intent before any dependency call. Lookup replays the same durable intent after restart, with bounded calls and no background retry loop. Clients resend the immutable command after an uncertain submission, regardless of earlier results. Identical command retries return the current operation; changed payload conflicts. Current access is checked even for a replay. New stale revisions conflict. Pending resolution excludes another financial command. A denied hold never presents protection; a denied resolution retains the case hold for review. Pending work carries a responsible operator and 24-hour follow-up.

Errors are stable codes: denied, unavailable, stale, conflict, late, prerequisites, evidence, invalid, pending. Clients translate all codes and preserve the same operation reference on uncertainty. No error returns evidence or private notes. Deterministic fixture providers are development-only; connected identity, receipt, evidence, Orders and assignment proofs remain required.

Evidence staging: `POST /v1/disputes/evidence/{subject_id}` streams at most five MB with media type, checksum and stable idempotency key. The injected protected `stage` method enforces quotas, retention, metadata stripping for images, signature/content validation and idempotent scoped storage, returning the Evidence schema. The supplied checksum verifies upload integrity before staging. The returned checksum and size describe the sanitized stored bytes, which may differ after metadata removal; downloads verify those stored values. No file name is sent. `GET /v1/disputes/evidence/{subject_id}/{reference}` requires current case access and a reference already attached to that case, including decision evidence. Protected `download` returns bounded bytes; checksum and current authority are checked again before returning a no-store base64 envelope. No public URL or preview is created. The protected provider must remove unattached files after seven days and retain active-case evidence under the approved retention policy.

Source additionally supplies a current permitted business responder set and a specific responsible operator identity. Reviewer independence excludes both parties and all current business responders. Each held state has a next action and 24-hour review; composition must schedule 48-hour escalation without progress.

## Private view delivery contract

The exact read key is `disputes.v1 / access fingerprint / order / selected business`; freshness is zero and warming is open-only. Current reads run only after explicit order selection. The leaf invokes the canonical read definition through an abortable in-memory reader because this route does not yet have the canonical shared read scope. No private answer is retained across unmount or access change. Locale is absent from form identity and request keys. Entered dollar text, notes, chosen file and pending operation remain in memory through presentation changes. Language changes do not invoke a read, submit or upload. Refresh drops the previous answer until current authority succeeds; denied access clears displayed private content. The first frame uses the root theme/font/provider order and a canonical skeleton only while the first answer is unavailable. No extra arrival animation is added.

Shared shell route registration, permitted gateway byte budgets (including base64 evidence response), canonical shared read-scope composition, data-on-intent, retained-answer refresh and measured route size remain composition requirements. No warming, retained-answer speed, size, first-frame visual or motion performance claim is made for this leaf. The page is a single order/case view and has no collection or client-side pagination. The single root shell continues to own direction, theme, safe areas and landmarks. Connected access, Orders, protected storage, durable-store deployment, escalation scheduling and the browser/physical-phone matrix are release prerequisites.

The owned screen is ready for composition through the existing root shell boundary. No route entry is published before its shared delivery registration; the route entry and registration must land together under the composition owner's scope. An authoritative denial unmounts the private form and reader, aborts requests and clears notes, drafts and private file controls. Only the operation reference remains for recovery; explicit reopening requires a fresh current-authority read.

A currently assigned independent reviewer may reconcile an existing financial operation through lookup after reassignment. The original immutable binding and financial operation reference are replayed unchanged; the former reviewer loses access. Commands revalidate current identity, scope, source and assignment revisions after evidence verification and before persistence.
