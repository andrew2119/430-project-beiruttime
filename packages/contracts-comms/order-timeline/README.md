# Order timeline v1

Read-only projection. Neither this response nor a retained answer permits payment, receipt, approval, work or release. All money is simulated USD integer cents. Source-confirmed means only that named milestone; paid funds do not establish receipt or completion.

Operations are listed in `index.ts`. Reads require a current identity and current record scope before and after source reads. Buyer and seller receive the same milestone projection. Business access additionally binds selected organization, current membership, assignment and revision. Never accept identity or scope from query parameters alone. Denied returns 403 with no record data; invalid input 422; missing/currently unreadable required source 503. All responses use private no-store caching.

The composition boundary accepts a current access provider and six versioned snapshot providers. Each call has a 300ms ceiling, no automatic retries, at most six concurrent calls per read. Runtime registration and concrete provider adapters remain with their owners. The access provider returns an immutable lease with actor, organization, order, watch and current access revision; it rechecks that exact lease after projection. The catalog returns only currently scoped readable references, a server total and stable ordered pagination, limited to 20 rows. It must bind its cursor snapshot to current identity and revision or reject stale pagination.

Every source snapshot binds order, watch, operation, source revision, state and authoritative UTC occurrence. Orders additionally supplies retained quote economics and explicit waiting party, since, next action, responsible operator and last progress time. No waiting party or authority is inferred from missing events. The source owns deduplication and current revision selection; this consumer accepts a complete current snapshot, never event arrival order. Duplicate snapshot reads have no side effects. Malformed, stale, mismatched or timed-out optional snapshots become unavailable independently; unavailable Orders fails the read. No evidence, contact details, serials, free-form notes or private file references enter the response.

Waiting follow-up is due at last progress plus 24 hours and escalated at plus 48 hours, including equality. These are reminders only, never payment expiry or release clocks. No source event is stored here; acknowledged changes remain with the source's durable receipt. Restart reconstructs this projection from current snapshots.

Fixtures cover success, denied, stale, partial timeout and lost response. They describe synthetic development responses, not connected acceptance. Connected NOTICE, O03, C14, O05 and S03 checks remain owed, including reordered events, denied access, timeout, restart and duplicate responses with actual providers.

The lease carries exactly one current expected revision for each of the six source names. A different revision is unavailable, including a later snapshot read across the lease boundary; retry obtains a fresh lease. Each milestone preserves its own source operation reference. Confirmed payments mean held simulated funds, custody means actual approved receipt, progress means recorded work completion, and settlement means confirmed simulated payout. None implies another milestone. Inspection is not applicable to the direct business route and must never be synthesized as a pass. Optional source quote bindings must exactly match retained Orders economics. Consumers exclude all undeclared response fields before retaining an answer.

Financial facts separately identify gross held funds, confirmed collected fees, price/job refunds, net proceeds and payout. Each preserves its own operation, revision, UTC time, exact cents and pending/blocked/confirmed state. Refund authorization is not a confirmed refund; retained fees are not collection. Payments and settlement supply bounded financial arrays; unavailable or mismatched snapshots contribute no financial facts. Empty arrays mean no recorded facts, never zero money or completed settlement.
