# Operational audit references v1

Private, read-only references for an operator with `audit.references.read` in the selected current organization. A reviewer or ordinary user has no combined-audit permission. Each owner must independently recheck current record scope and assignment on every page and operation lookup. No cross-database reads, raw evidence, free-text reasons, file links, serials, ceilings or financial execution are permitted.

The additive module exposes `GET /v1/audit-references` with the `AuditQuery` fields as query parameters and an optional `source` selecting one owner. Each source independently returns `ready`, `empty`, `denied`, `stale`, `pending` or `unavailable`, plus a validated page only for ready/empty. Date bounds are authoritative UTC, inclusive after and exclusive before, at most 31 days. Page size is 1–50; offset is at most 10000. Larger histories must narrow their date/resource filters. Ordering is descending occurrence instant then operation reference. Totals belong to each owner, never a combined guessed count.

Owners expose `GET /internal/v1/audit-references` with the identical query, plus `GET /internal/v1/audit-references/operations/{operation_id}` for an exact operation and revision. The combined lookup is `GET /v1/audit-references/operations/{operation_id}?source=...&organization_id=...&expected_revision=...`. Lookup responses are exact `AuditReference` objects and are validated against the requested operation, organization and revision. The reason reference and revision identify the owner's retained reason record; they are not private evidence URLs.

The authenticated bearer is forwarded only to the named owner. Query operation references survive retries and may be re-entered after restart; identical GET requests are safe to repeat. There are no local mutations, receipts, files, financial decisions or acknowledged changes to lose. Owners retain acknowledged changes. Timeout never means success; restart re-reads actual owner facts. A source revision mismatch requires fresh explicit filters, not silently substituted history. Responses use `Cache-Control: no-store`. The browser holds private answers in access-partitioned memory only and drops displayed answers on any read failure.

Owner responses must echo the exact query and reader. A revision is a source snapshot binding, never permission. Owner 202 is pending; 403 is denied; 409 is stale; other errors, malformed responses and timeouts are unavailable. Requests have finite deadlines, no automatic retries and bounded response bodies. No fallback source exists.
