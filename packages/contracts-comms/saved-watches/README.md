# Private saved watches v1

Commands, lookup and reads require current personal identity. There is no organization-owned list. A caller cannot nominate a different owner. Initial revision is zero; removals retain a revision tombstone. Mutations and their immutable operation receipt commit together. A retry uses the original operation and payload, including after an uncertain response. Lookup returning no receipt is pending, never permission to invent success. No financial or custody authority is published.

The source port returns only public watch facts: watch identity, monotonic source revision, available/sold/unavailable state, public title, integer USD cents, public bid sequence, fixed scheduled-end UTC instant, canonical event occurrence UTC instant, sample marker and canonical cancellation status. No private ceiling, evidence or recipient address crosses this boundary. A source invalidation triggers a fresh canonical read; its payload is never a sale or ending fact. Price and bid alerts require an observed change; first saves establish the initial source snapshot. Ending becomes due at scheduled end minus 30 minutes and is obsolete at equality with end. Withdrawal, no-bid cancellation and an amended scheduled end suppress old pending ending claims. Removed public details remain a labeled saved row.

The source, identity and inbox ports must use authenticated, bounded calls, with a maximum two-second invocation including body reads and no hidden retries. Uncertain authority fails closed. The inbox receiver must atomically deduplicate `notice_id`, recheck current personal access, save revision (a retry may retain an older save revision only while its category subscription has remained continuously enabled) and canonical source revision (for a historical price, bid or sold occurrence, a newer revision is permitted only while the current source remains compatible: available and uncancelled for price/bid, sold for sold; for an ending-only claim, a newer revision is permitted only with the identical scheduled end and current available, uncancelled state), and commit personal inbox availability before acknowledging. Notice opening rechecks current watch access. Optional saved notices never substitute for, suppress or change required outbid notices. A failed recipient channel cannot remove a committed personal inbox notice. No live channel delivery is represented here.

`schema.json` validates the immutable command. `contract.json` gives operation paths and revision/error rules. `fixtures.json` is deterministic sample data for success, denial, stale revision and uncertain/lost responses. The immutable result envelope is declared in `index.ts`; organization, review actor and review time are null for personal saves. These are local contract fixtures, not connected acceptance.

Receipts retain the source revision for a new save. Preference-only changes and removals use an explicit null because they assert no source fact. The owner-private record read includes removed-row revisions so saving again can review the current tombstone before committing. An older or conflicting canonical response never restores an obsolete availability label.

Public change notices retain the canonical occurrence time rather than polling time. Ending occurrence is scheduled end minus 30 minutes. Delivery retries retain the original immutable occurrence payload; a newer ordinary bid revision cannot erase an unchanged fixed-end claim.

Canonical read watermarks are retained separately from the alert observation snapshot. Reading newer public facts prevents older facts from restoring availability without consuming an undispatched change. Preference updates retaining ending keep the original occurrence payload and action binding; disabling ending or removing the save retires its pending occurrence.

The private record read includes nullable `ending_since_revision`, the start of the current uninterrupted ending subscription. The receiver accepts an older ending `save_revision` only when the current saved record still enables ending and `ending_since_revision <= save_revision <= revision`. Disabling ending or removal clears this binding atomically; a later opt-in starts a new binding.

A notice describes its retained occurrence, not a claim that its source revision is still latest. Unrelated newer revisions do not erase a price change, bid or sale. The receiver preserves the immutable source revision and occurrence time while rechecking current compatible state; withdrawn or cancelled stock suppresses price and bid claims.

Every enabled category has an owner-private `alert_subscriptions` entry with `since_revision` and canonical `source_revision` at opt-in. The store also retains the public facts at that boundary so later unrelated revisions cannot turn earlier activity into a new change. Price, bid and sold occurrences must be newer than that source boundary. A receiver accepts an older save revision only inside the category’s uninterrupted subscription, bounded by the current record revision. Unrelated preference edits preserve immutable queued occurrences. Disabling a category or removing the save retires its pending occurrences; re-enabling establishes a new boundary without consuming changes owed to other owners.

Canonical price, bid and sold activity is read through the retained occurrence operation in `contract.json`. Each occurrence carries its own immutable identity, source revision, UTC event time and sample marker. A complete bounded batch includes all activity after the observation revision through the requested revision, including changes that later reverse. An unavailable or incomplete batch leaves observation unchanged. The latest public snapshot only controls current compatibility; it cannot supply occurrence metadata. Ending occurrences continue to use the canonical fixed scheduled end.

Held notices retain a responsible operator identifier, escalation operator identifier, next action, hold time, 24-hour response deadline and 48-hour escalation deadline. Current scoped permission governs recovery reads and reconciliation. A reconciliation response uses a stable operation reference and expected recovery revision and authorizes a bounded retry cycle of the original notice, never a replacement notice. Unresolved cases escalate at equality with the escalation deadline. Assignment and escalation scheduling are required composition dependencies, not connected proof.
