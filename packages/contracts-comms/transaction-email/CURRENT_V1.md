# Transaction email v1

Private synthetic records only. No transport, credentials, address, evidence, amount or private message body enters a response, event or diagnostic output.

An authenticated producer captures a Command after obtaining fresh Authority from the owning source and identity/recipient provider. The provider must serialize its current permission, organization, assignment, watch/source revision, retained quote/policy, actual occurrence and verified recipient checks with admission. A verification applies only to the exact current recipient revision. A source projection is insufficient. The source must supply actual facts for each message category; this module invents none.

Operations: POST /internal/v1/transaction-email captures; GET /v1/transaction-email/operations/{operation_id} looks up the stable receipt; GET /v1/transaction-email lists private records with offset/limit and server total; POST /v1/transaction-email/operations/{operation_id}/destination rechecks current access before returning a same-origin route. Authentication comes from the host's current principal dependency, never body actor headers. Capture is for authenticated communications producers only. User routes cannot invoke capture or delivery.

Every read and retry obtains fresh current authority. Denied is 403, stale revision or conflicting operation/event is 409, invalid input is 422, missing operation is 404, unavailable/timeout is 503. Errors expose only a code; views translate recovery. No failed authority check returns private history. Duplicate exact commands return the same operation/attempt; conflicting reuse denies. Event deduplication spans operation references within recipient and organization scope.

Durable capture includes the verified-recipient revision and availability timestamp. Captured is not delivery. Before a synthetic attempt, possibly_sent and the stable attempt identity commit atomically. Restart or response loss never blindly repeats that attempt. Recorded is only a synthetic result; failed leaves the independent inbox/source untouched. An uncertain attempt assigns support with a review instant 24 hours later. No payment-clock receipt is emitted here: inbox availability and its receipt remain independently owned.

The authenticated link contains only an operation reference and locale. It carries no authorization and no bearer secret. Opening requires sign-in and current source scope. No private email body is exposed in previews. EN/AR templates have identical meaning. Bounds: 4 KiB command, 20 default/50 maximum page size, 100000 maximum offset, two-second dependency limit, one synthetic attempt, no files, no automatic retries. UTC instants are authoritative; the view formats them in Asia/Beirut.

Composition requires a durable private store, the current-authority provider and current-principal/producer dependencies. The store must be on private service storage with host-managed access. The additive route factory does not register itself or replace an inbox, source authority or financial journal.

The fresh Authority names a responsible support actor. Uncertain/failed delivery preserves that exact actor and a UTC review deadline; the module does not invent an assignment. The captured private payload retains template version, rendered EN/AR text, source occurrence and verified-recipient revision so later wording changes cannot rewrite a prior record. Lists expose only minimal references and delivery state, never that payload.

The current-authority provider is callable for a single Command and also exposes async scope(actor_id, organization_id) returning ReadScope. Before any list or total, scope rechecks current membership and all currently readable subject identifiers (at most 10000). The private store intersects both rows and totals with those subjects. An absent, denied, malformed or timed-out scope fails closed even for an empty or out-of-range page. Per-record current Authority checks still apply to every returned row. Provider scope and record results must come from current source permission operations, never cached membership or a read projection.

Write admission requires async provider.admit(command, actor_id, organization_id, commit). The provider serializes current source permission, membership, recipient verification and revision changes against the synchronous commit(current_authority) callback, retaining that exclusion until the callback returns after durable commit. It must call exactly once and return its result. A prior callable snapshot never authorizes admission. Missing admission support fails unavailable; there is no snapshot fallback. The two-second budget includes admission. A lost admission response is retried using the same operation reference. Connected implementation and exclusion proof remain owed by the current-source provider.

The route entry is retained in the feature subtree for the composition owner. No application route is mounted until that owner registers the delivery contract and shared shell under its own lease.
