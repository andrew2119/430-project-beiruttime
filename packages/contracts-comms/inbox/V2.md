# Communications events v2

The authenticated receiver accepts only the registered producer and event type.
Payment-action-required v3 data binds order, buyer, revision and sample marker.
The envelope subject is the order reference. Outbid v2 subject is the auction
reference; quote-created v3 uses NoticeInput and its quote reference as subject.
Quote preferences never suppress required payment, outbid or case notices.

Payment availability is the database time of the first committed inbox insertion,
not event occurrence or delivery retry time. The same transaction writes the
synthetic verified-recipient record and immutable receipt intent. Nothing is sent
before commit. One order has one original availability receipt. Changed event,
buyer or revision conflicts; it cannot restart availability. Read/clear leave it
intact. The receipt contains exactly the fields in PaymentNoticeReceiptV3.

The payment lookup operation requires the authenticated communications producer.
It returns the original receipt and pending/acknowledged status. Only an exact
receipt response acknowledges delivery. Refusal, timeout, lost response and
malformed response retain the intent and retry the same receipt. Acknowledgment
never authorizes payment, receipt of goods or release of funds.

Schemas reject additional fields. Changed source facts require current-state
review; older events never rewrite an existing notice. An unavailable dependency
remains unavailable. The deterministic fixtures describe local contracts;
connected producer compatibility remains required before acceptance.

Receipt schema activation and the receipt worker remain deferred until module
discovery supports L22 registrations and migrations. The deferred registration
is metadata only and is not discovered at startup. Until activation, new event
subscriptions and receipt lookup return unavailable without writes; the original
receiver continues using its existing durable receipt boundary. Activate the
schema before enabling the receipt worker or relay destinations.
