# Browser push v1

Personal devices only; represented organization sessions deny. The current authenticated subject and access revision are resolved for every request, dispatch and click. A caller cannot supply identity. Commands bind the immutable operation, device, actor, session, access revision and expected device revision. Exact retries return the retained receipt after current authority checks; changed retries conflict. A lost response means pending: look up or retry the same operation. Denied permission leaves inbox unchanged.

Opt in and rebind require explicit granted permission and a fresh subscription. Rebind requires proof of possession through the authenticated session's device capability, issued by the host, never a caller-chosen device identifier alone. Endpoints and encryption keys never appear in receipts or logs. The host must validate endpoints against its delivery provider allowlist; the dispatch port must not perform unrestricted URL requests.

The host supplies bounded current identity, inbox occurrence/access and encrypted delivery ports. Inbox occurrence is committed before scheduling delivery. Only actual outbid, win, message and action-needed notices qualify. Generic bilingual text contains no source payload, contact, evidence, amounts or record identifiers. Clicks open the canonical inbox; opening its record rechecks current access. An old click never grants record access.

The device capability is a secure, same-origin, HttpOnly host cookie, bound to the installation; it must survive session rotation but cannot be inferred from a device ID. Logout revocation must finish before identity logout acknowledgement. Account switch revokes the old session before accepting the new binding. Host composition and actual provider proof remain required; no new root worker or shared runtime registration is supplied here.

The durable adapter is hosted in one process with one module store per private persistent database. It shares the delivery/revocation lock across instances of that store in the process. Multiple independent processes against the same file are unsupported; a shared transactional delivery coordinator is required before scaling. Revoked-session tombstones prevent late commands from resurrecting a logged-out binding. Host encryption protects endpoint material at rest and must use a stable release-managed key. Receipt and delivery retention follow the host's minimal-reference retention policy.

## Port freezes

`current_identity(credential)` returns the current `{actor, session, access_revision, organization}` or denies; it never trusts actor fields in a request. The session is an immutable login reference. Each dependency call has a three-second bound. No delivery uses a browser access token retained from opt in; the host worker supplies a short-lived credential for current delivery admission.

`inbox(identity, notice_id)` is the `browser-push.inbox.v1` private adapter: return `null` on absent or revoked access, otherwise `{schema_version:"browser-push.inbox.v1", recipient_id, available, kind, expires_at}`. `available` means the canonical personal notice is already durably committed and currently accessible. `kind` is `outbid`, `win`, `message` or `action_needed`. `expires_at` is an authoritative offset-bearing UTC instant; equality expires delivery. The adapter resolves actual current record and organization scope, never a projection alone. It never returns private evidence. Inbox read/clear or payment-clock mutation is not part of this port.

`delivery(subscription, {schema_version:"browser-push.v1",kind:"notice"}, delivery_key)` returns `sent`, `gone`, `denied`, `pending` or `failed`. It honors the same stable key after uncertain responses and restart; it has no authority over inbox availability. Gone/denied invalidates only the dispatched binding revision. Three attempts are allowed per notice/device/revision; the host schedules finite backoff and records support follow-up for exhausted uncertainty. `protect` and `reveal` encrypt/decrypt bounded subscription material without logging it.

`GET /v1/browser-push/config` returns `{application_server_key:string}` only for a currently authenticated personal session; missing provider configuration returns unavailable. This key is public subscription configuration, never a delivery credential. The host must also mount the secure device-capability issuance/validation boundary before enabling this page.
