# Wrist measurement v1

`GET /v1/fit-measurement/context?subject_id=…&watch_id=…&organization_id=…` returns the current scoped source revision and optional recorded target. `POST /v1/fit-measurement/records` accepts `FitCommand` and returns `FitRecord`. No files or free-form notes are accepted. Request bodies are bounded to 2 KiB. Measurements are private, not public event payloads.

An integer millimeter value retains exact meaning. Allowed range is 80–300 mm inclusive, a correction guard rather than a clinical judgment. One decimal digit in centimeters is supported. Millimeters must resolve to whole millimeters. ASCII and Arabic decimal points are accepted; grouping, commas, signs, exponents and mixed separators are rejected. An explicit suffix must match the selected unit. Buyer measurement, method and desired fit are retained; `final_fit_pass` must be false and cannot authorize quality, work, payment or release.

Current authority is required on every read and write, including duplicate retries. Only the buyer may write. The buyer and currently assigned business staff with record-read permission may read; business access never grants write authority. The source provider must bind actor, buyer, organization, watch, current commitment and source revision, plus any applicable assignment, accepted scope and retained policy/economics. A projection is insufficient. The provider executes within the protected write transaction and holds its current authorization fence until commit. Missing or uncertain proof returns 503, never success. Cross-account or revoked scope returns 403. Source or record revision mismatch returns 409. Provider calls have a 1.2-second budget. The runtime owner supplies this provider and the pool; no fixture is a production provider.

Operation identity is bound to actor, business, subject, watch, source revision and the complete immutable command. Same-reference retries return the retained result after current authorization. Changed payloads return 409. Records, receipts and a private-reference-only outbox entry commit atomically. A lost response is retried with the same body and operation reference. No automatic retry loop is specified. Timestamps are authoritative UTC; this operation has no civil appointment or money input.

Fixtures are synthetic contract examples, not connected acceptance. Runtime route composition, current directory/identity/commitment proof, database execution and downstream outbox delivery remain required before connected acceptance.
