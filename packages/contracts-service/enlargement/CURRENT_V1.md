# Enlargement v1

`POST /v1/enlargement/commands` accepts the strict Command schema in `v1.py`.
`GET /v1/enlargement/requests/{request_id}` requires current record access.
Operation lookup is `OPERATIONS`; versions and operation references are immutable.
The request identity, selected business, canonical watch, source revision and actor bind every receipt. Identical retries return the retained result after current access is checked. Conflicting references deny. A lost response requires the same reference and payload. Pending dependencies never advance the record.

Requests preserve source measurement and exact millimeter conversion, method, source and target. Supported choices are actual compatible links, strap or clasp. Assessment requires the actual part identifier, revision, quantity and supplied/ordered/available/unavailable status from the provider. There is no conversion from circumference to link count or assumed clasp travel. Ordered or unavailable parts produce waiting with a responsible business and next review, never completed work. Alternatives need a new assessment and customer acceptance.

Assessment quotes come from current retained USD economics. The buyer explicitly accepts the current quote and all mandatory/chosen optional lines before expiry. Work requires current scope, custody, confirmed held payment, independent approval and actual available compatible parts. Quality records tests, actual fit and returned parts with an independent reviewer. Fit recorded does not imply receipt, release, history publication or financial completion.

Current provider interface: `current(actor_id, command)` returns actor, buyer, organization, watch, source revision, active/authorized, role, assignment, capability and canonical commitment facts. It supplies exact quote and part snapshots and current acceptance/custody/payment/approval/independence/incident/quality decisions. Missing facts fail closed. The adapter must enforce a bounded call deadline and current authorization serialized with command admission. No cache grants execution permission. No private evidence is accepted by this interface.

Errors: denied (403), stale/state/quote/expired/parts/work_held/quality/operation_conflict (409), invalid input (422), unavailable (503). Error bodies contain codes only; never private payloads. Waiting and unavailable display recovery in both languages. Authoritative timestamps are UTC with a `Z` suffix. No appointment is booked here.

The durable local store atomically writes state, receipt and a minimal outbox event. Runtime composition must provide durable storage and bridge the outbox through the service's existing delivery owner; it must not create another financial journal or allocation. Runtime registration and connected producer proof are separate prerequisites.

Quote snapshots contain `base_minor`, zero `buyer_fee_minor`, `business_fee_minor` and `total_minor`. The customer total equals the job base; the business fee is five percent rounded half up. Each accepted quote line has `{id,label_en,label_ar,amount_minor}`, unique identifiers and a sum equal to the customer total. `terms` contains complete `en` and `ar` text. All lines returned in this snapshot are the mandatory and chosen optional lines, not unselected alternatives. Acceptance binds every exact line identifier and the terms revision. Work explicitly confirms every accepted line before a worked state. Reassessment removes old acceptance, work and quality. Missing parts discovered at work admission return a durable waiting state. Current part identity, kind and revision must match the assessment, with an integer available quantity at least as large as the assessed quantity. Failed quality enters `rework`; corrective work removes the obsolete quality before another check.

Provider calls have a two-second maximum wait, a 64-KiB response budget and one in-flight slot per service instance. A timed-out call cannot advance state or enqueue additional calls behind it. Admission holds the local record transaction across the current-facts check. The connected provider must serialize its authorization facts with this admission boundary; local fixtures do not establish distributed authorization serialization.

Reassessment is permitted from accepted, worked and rework states. It invalidates acceptance, work and quality and requires renewed explicit acceptance. Parts waiting requires current provider fields `responsible_operator_id` and bilingual `next_action`. The first waiting admission retains `waiting_since`, `first_response_due_at` (24 hours) and `escalation_at` (48 hours without progress); another waiting admission never resets these boundaries. `next_review_at` must be future and within 24 hours of the current admission. Later follow-ups preserve the original response and escalation boundaries, including overdue boundaries. Runtime delivery must schedule the retained follow-up and escalation through the existing delivery owner.

Rework is a held state with the same current responsible operator, bilingual next action, future review within 24 hours, and retained 24-hour response and 48-hour escalation obligations as parts waiting. The retained `waiting_since` field anchors either held state. Corrective work clears these obligations only when it advances to worked.
