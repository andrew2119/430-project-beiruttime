# Progress v1

`GET /v1/progress/{subject_id}?offset=0` returns up to 50 accepted lines, server total, next offset, current aggregate and revision. `POST /v1/progress/{subject_id}` accepts Command. `GET /v1/progress/{subject_id}/operations/{operation_id}` recovers the exact acknowledged result. All endpoints are private and recheck current access. No files or evidence references are accepted. Reports contain customer-visible bilingual descriptions only; restricted evidence belongs in intake.

The composition supplies `progress_access(request)` and `progress_source(access, subject_id)` as asynchronous current-provider adapters. Each is bounded to 1.2 seconds. The latter returns Source from current identity, business membership, job assignment, accepted scope/economics, canonical watch commitment, custody, Orders payment and independent quality facts. A cached projection is not this provider. Missing adapters, timeout or invalid responses yield unavailable. The source lease must remain current inside the serialized command transaction. Runtime composition and actual provider proofs remain separate prerequisites.

A buyer reads only its own job. Business staff read only the selected business and assigned job with current record permission; writes additionally require job permission. Commands bind the full Binding and expected local revision. Stable operation identifiers bind actor, selected business, subject, watch, source/scope/quote/policy revisions and exact payload. Same operation and payload returns the original receipt after current access checks; conflicts deny. A lost response requires operation lookup or retry of the identical command, never a new identifier. Provider failures never imply success.

Accepted lines alone appear. Required incomplete work forbids readiness. A material change pauses affected work until renewed accepted scope arrives. Missing custody, held payment, acceptance, or any incident holds work; incident also holds readiness. Quality is consumed only when independent and bound to current scope and local work revision. Progress never records quality approval, payment, custody, receipt, release or financial balances. Waiting states carry attributable since-time, a responsible assigned colleague, next review and manual follow-up. A missed review only becomes overdue at equality; it never completes work or substitutes a part.

All instants are UTC; display uses Asia/Beirut. Estimates are ranges with bilingual basis, not appointments or promises. USD retained amounts are integer cents. Source lines are bounded to 1,000; report text is bounded and HTTP bodies are bounded to 32 KiB. Public outbox facts contain only job, business, watch, revision and operation references. Private descriptions do not enter events or logs.

Every source snapshot also supplies the current responsible follow-up actor, bilingual next action and UTC next review, including held jobs without reports. An empty accepted scope is representable but never ready. Every accepted line, including chosen optional work, must be complete. Reports whose watch, business, subject, scope, retained quote or policy binding differs are retained as history only and excluded from the current view.

The owned composition description is `composition.json`, intentionally outside automatic module discovery: current discovery admits only earlier lane identifiers. Its steward must extend discovery and install this composition, migration and current-source adapters together. This leaf does not register itself into a shared runtime.

The transaction-local outbox retains `service.progress.reported.v1` facts pending delivery. No delivery is claimed by inserting a row. The composition steward must attach a bounded relay and durable consumer inbox keyed by operation identifier, with stable retries; that connected proof is deferred. Timeline consumers may display these reference-only facts but must never interpret them as permission to execute, charge, receive, approve or release. No private report content is sent in this event.
