# Authorized work v1

Private commands and operation lookups use the same actor, organization, job and watch partition. No public projection, event or preview includes notes, readings or part references. No file upload is accepted here; restricted evidence stays with its permission-scoped producer.

The immutable command binds current source, retained quote and policy revisions. Orders must validate current identity, business capability, assignment, accepted lines, canonical watch commitment, custody and held payment on every read and write. A declined quote permits only controlled unrepaired return. Historic retained economics confer no execution permission. All active money remains retained integer USD cents in Orders; this module never charges or owns balances.

`POST /internal/v1/authorized-work/commands` and `GET /internal/v1/authorized-work/operations/{operation_id}` are the additive composition boundary. Responses contain schema_version, operation_id, subject_id, watch_id, actor_id, organization_id, expected_revision, state, revision, pending_reason, next_actor and next_review_at. States are recorded, pending and paused. Denied and stale are typed errors. A duplicate with different bytes conflicts. Unknown results retry the exact operation. Authentication and bounded provider adapters must be supplied by runtime composition before these operations are exposed.

The provider implements `authorize(command, actor_id, organization_id, now)` and `hold(command)`. Calls have a two-second deadline. A hold response must bind operation/job/watch/source revision and durably block work, handover and payout while invalidating old quality. The operation intent and pending pause survive restart before any remote hold request. Reconciliation resends the same operation; conflicting receipts remain pending. Missing provider, timeout or malformed authority never confirms work. Current authority is rechecked even on duplicate and lookup.

Observations use UTC instants, never civil appointment inputs. Required lines must all have actual progress before local completeness is true; completeness is never quality, receipt or release permission. An incident retains previous observations and original condition at the custody producer. No local resume command removes a pause. Renewal and incident resolution belong to current Orders authorization and a subsequent versioned composition.

Connected prerequisites C14, S02, O05 and O06 remain deferred. Local fixtures prove only this boundary. Re-run denied, stale, lost-response, duplicate and restart cases with actual providers before connected acceptance.


`context(subject, actor, organization, now)` is the provider's current assigned private-read check, independent of historic work execution permission. It returns Authority for that exact scope and a verified responsible_actor_id. `authorize` additionally validates execution and the responsible next actor. A scoped historic lookup does not demand that its old quote is still current. Local pre-write stale/deadline rejections retain immutable rejection receipts; only these return not_applied, allowing a reviewed fresh command. An uncertain receipt never clears the reference. Conflicting durable hold revisions remain pending for reconciliation.

The local persistence adapter uses a supplied private database file and its additive L19 migration. It is not registered in the shared runtime. The runtime steward must supply database placement, authenticated bounded producers, current read/command permission adapters, durable reconciliation scheduling and the journal-backed hold operation before exposure. Escalation is due 48 hours after a held observation without progress; the responsible next review is bounded to 24 hours. No claim of automatic escalation delivery is made by this module.

The feature declares `/business/work` in its local delivery contract and uses the shared page composition. Shared shell and private read-scope adoption remain deferred to their owner. No second scope provider is mounted here. The reads are `authorized-work.v1` keyed by current access fingerprint and subject, and `authorized-work-history.v1` with the same partition plus offset. Both use open-only warming and zero freshness; retained answers are suppressed on confirmed access denial. First-frame, arrival, measured size and connected navigation proof remain deferred until shared composition is available.

Retained hold intents reconcile through the identical command reference and immutable body after a current assigned private custody check for actor, organization, job and watch. Changed current quote, policy or source revisions do not rewrite or strand the original hold bindings. New observations still require current revision authorization. Denied access and a changed watch block reconciliation.

A wrong responsible-person reference is a definitive `responsible_actor` rejection. Its immutable rejection receipt survives restart and returns `not_applied:true`; correction uses a new operation reference. Existing uncertain operations retain their original reference and body.

Loss and damage use the current assigned private custody check through `context`, including pending payment and declined unpaid jobs awaiting controlled return. They retain exact scope/revision bindings and responsible-person checks, but do not require execution permission or held payment. Missing current custody, expired permission or denied scope cannot record an incident. Progress and material changes continue to require current execution authorization and confirmed held payment.

Progress rejected because the job is paused receives a durable immutable rejection receipt with `not_applied:true`. The draft may then be corrected under a new operation reference, including reporting another incident; the paused job remains paused. Uncertain operations keep their original reference.

New observation preparation obtains a fresh scoped server response for the observation instant and one-hour next review. Before and after readings carry separately entered UTC instants, checked against that response and again against command admission time. Preparation failure sends no command. The prepared command retains all instants and its operation reference unchanged across retries and language changes.
