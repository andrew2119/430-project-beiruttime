# Auction policy v1

Kernel consumes pure synchronous `auction.policy.accepted-bid.v1(state)` once per admitted manual/maximum command with public bid rows, inside the existing canonical bid transaction. State has aware `ends_at`, authoritative `server_time`, positive `end_version`, `extension_policy`. An additive compatibility alias `auction.extension.v1(state,bid)` accepts the initial kernel handoff shape (`bid.accepted_at`, `bid.public_bid`). Both call the same pure rule; the kernel invokes only one. Output has ISO `ends_at`, `end_version`, `extended`. Exactly 120 seconds remaining qualifies; zero or negative denies. Extend **current end by 120**, once per command even if proxy emits multiple rows. Replay does not call the hook. None policy leaves time/version unchanged. A private cap-only raise does not extend. Kernel atomically persists result with bid/outbox; stale close/ending work must compare both mode and end_version. Reserve predicate uses public current price, never private cap.

Policy configuration remains editable only by current seller before first admitted bid, first-bid intent, or prebid freeze. `auction_lots.buy_now_minor` is canonical for the L14 quote-context seam; an additive L12 migration projects old settings into that column and guards it against post-commitment changes. The old settings table is retained only as a rollout projection. Reserve/increments are configured by existing rules API and remain frozen; L12 does not weaken its trigger. L14 owns additive sanctioned extension migration/kernel integration.

Public GET /v1/auctions/{id}/policy, seller PATCH same endpoint (If-Match and Idempotency-Key), buyer POST /v1/auctions/{id}/prebid-buy-now, GET /v1/prebid-operations/{key} and GET /v1/auctions/{id}/my-prebid. The latter restores only the current buyer's operation on a fresh page, without a remembered key. Exact bounded body types in models.py / index.ts. Private operation read requires same current buyer. No reserve amount or maxima in public policy/events.

Pricing construction uses the published L14 browser aliases: POST `/v1/auction-quotes` with `{auction_id,expected_revision}` returns a succeeded operation containing the retained `quote`; POST `/v1/auction-quotes/{id}/review` with `{quote_revision,payable_minor}` explicitly reviews it; GET `/v1/auction-quotes/{id}` reads the actor-owned snapshot. Snapshot `kind=prebid`, `purpose=purchase`, source `auction` and verified physical/listing/revision fields are required. No client-entered price can create this quote. Old v1 manual/proxy fee previews remain unchanged.

Prebid protocol: under kernel's same auction lock, require live/server_time < current end, no accepted bid, current revision, positive frozen buy_now_minor, individual non-seller/non-member buyer, current quote. Persist operation + prebid_pending mode **before** Orders HTTP. Commit, call Orders commitment v2 with stable operation ID and immutable watch/listing/auction/buyer/quote binding. Unknown/lost response stays pending. Read Orders operation using the same ID, never invent another reservation and never reopen bidding on timeout, 404, or denial. Success advances to prebid_reserved under same kernel lock and enqueues safe fact intent. Close/rules/bids must reject both pending and reserved modes. Retry reconciles same intent. No standalone physical fence or journal.

Private quote validation seam: `GET /internal/v1/auctions/{auction_id}/prebid-basis?quote_id={uuid}&buyer_id={uuid}` requires an RS256 service token, audience `auction`, current issuer, type `service`, producer `pricing` or `orders`. User access tokens and other services deny. Exact `PrebidQuoteBasis` in models.py binds the persisted quote/buyer/watch/listing/amount/currency and **admission_revision R**, even though pending/reserved freeze advances canonical revision to R+1/R+2. Pricing validates its retained quote against admission_revision plus this current exact intent, not a guessed `current_revision-1`. Wrong quote/buyer is 404; denied, changed or legacy unprovable intent is 409; absent verifier/kernel is 503. The endpoint is not browser-gateway registered and never emits these private bindings publicly.

New features return explicit unavailable if kernel v2 is not installed; module registration and original v1 routes continue to boot. No alternative lock/engine is used.
