# Two-factor current operations, version 1

All endpoints are private, authenticated internal operations. The identity runtime composes this additive module; it must not expose internal recovery or acknowledgement endpoints to ordinary sessions. The browser uses its same-origin authenticated route adapter. No endpoint is registered by this module alone.

Commands use `current.py`; operation lookup uses the same current identity and organization checks as writes. Results use `current.ts`. An operation identifier is immutable within a subject and stores an encrypted result. Secret-bearing receipts require the issuing session and current factor generation; reset and replacement enrollment invalidate earlier private results. Lookup binds the original actor, organization, action, record and revision rather than caller-selected scope. Identical retries return that result after current authority is checked; changed payloads conflict. Unknown lookup is unavailable, never success. After acknowledged recovery, its pending receipt resolves to sign-in required with the current revision for an authorized fresh session. Error codes are `denied`, `stale_revision`, `conflict`, `invalid_proof`, `expired`, `try_later`, `unavailable`. Uncertain transport returns pending and retries the original identifier.

Enrollment expires after ten minutes and does not enable a factor until a six-digit TOTP confirms it. TOTP uses a 30-second step with one step of clock tolerance, accepting a step only once, including enrollment. Numeric Arabic forms normalize without changing the code. Ten random recovery codes are delivered only through private encrypted operation results; only keyed digests are retained in factor records. Secret encryption authenticates the subject as additional data. Keys are supplied by the identity runtime and never stored here.

Proofs expire after five minutes, strictly at equality. A proof binds actor, current session, organization, sensitive action, record identifier and exact record revision. Consume is one-use and must be called by the authenticated protected-operation producer, with its current capability and revision checks. A consumer must serialize consume with its own durable action receipt; retry its original operation after uncertainty. No projection grants execution permission. This module never changes payout recipients or verifies them.

Authority is a current provider result, bounded by the runtime to a finite timeout. It checks active identity, session, selected business membership, exact record permission, assignment, independence and source revision. It returns false for missing facts. Enrollment and recovery require recent current-password proof. Recovery additionally requires two distinct independently authorized controllers, neither the subject, and an exact case binding. Controller authorization is resolved by the provider, never accepted from request fields. Reset clears the factor and proofs, queues a stable session-revocation reference, and remains pending until the identity producer acknowledges durable revocation of every session and refresh family. Old sessions cannot enroll during pending recovery. Acknowledgement requires the authenticated identity producer and exact reference. New enrollment requires a new signed-in session after acknowledgement. Replacement enrollment of an enabled factor is refused; factor changes use controlled recovery and revoke sessions.

Private results, TOTP, codes, keys and enrollment secrets must be excluded from events, logs, previews, browser persistence and shared query caches. Responses require `Cache-Control: no-store`. Clear mounted private state on access-fingerprint changes. Operation lookup is a private recovery channel for a lost response, never public evidence.

The durable local repository is an executable provider fixture. The service-owned database adapter and additive migration retain encrypted state, stable receipts and a revocation outbox atomically. Database execution proof, runtime composition, current identity/assignment provider, transactional protected-operation consumption, session-revocation delivery and connected timeout/restart acceptance remain required before enabling routes. Calls fail closed when these providers are absent.
