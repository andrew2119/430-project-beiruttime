# Personal data requests v1

Private current-operation interface, policy D31.v1. A person may act only on their own account, inside their current selected organization scope. Recheck current identity, membership, scope and revision on every read, command, receipt and export download. Authentication supplies scope; request bodies cannot grant it. No private file references appear in responses, events, previews or logs.

Proposed routes under `/v1/data-requests`: POST accepts DataCommand; GET accepts page (zero-based) and page_size (1–50); GET `/operations/{operation_id}` looks up the exact stable reference; GET `/operations/{operation_id}/export` streams a private attachment through a fresh access check with no-store and no public redirect. The composition owner supplies authentication, current authority, transport and file delivery. These routes are not registered by this module.

Create is revision zero. Domain receipts require their immutable per-domain command revision (independent of the aggregate operation revision) and a stable receipt ID. Identical duplicates return the current result; conflicting duplicates deny. Unknown/lost responses use the same reference and lookup, never a new request. Errors are `denied`, `stale`, `conflict`, `invalid`, `unavailable`, `limit`. No raw dependency exception is returned. Missing or timed-out domains remain pending/partial; no nine-domain success is inferred.

Each domain receives one private outbox command with the operation, actor, organization, subject, expected revision and policy. Domain source authority checks its own current records; no projection authorizes deletion. The transport enforces a finite timeout and authenticated producer identity, and acknowledges delivery only through a durable receipt. Each command keeps its initial revision and payload through retries. Assemble requires the current aggregate operation revision. Dispatch at most 9 entries per pass, at most 5 attempts per entry with a stable command ID; exhaustion requires operator recovery on that same command. The receipt binds domain, operation, source_revision, facts_revision, policy and result. Reasons use the closed HoldReason vocabulary; no free-form evidence enters audit metadata. Receipts for retained records must state every applicable obligation and a next review time. Closure needs a newer authoritative source revision; a changed obligations snapshot requires a new receipt. Export redaction covers third-party private information.

Unsubmitted private uploads expire at creation +7 days. Synthetic identity/possession proof expires at final review +30 days unless the source confirms an active case. Minimal audit references expire at the UTC calendar anniversary (29 February becomes 28 February). Deletion/redaction is due 30 days after the last active obligation closes. Export is due within 7 days of request. Private assembled exports expire after 24 hours, a bounded link default. Export files are capped at 20 and 25 MiB combined. Expiry denies access immediately; file removal failures remain partial until acknowledged. Minimal audit holds do not retain original evidence. Cleanup uses the same delete/acknowledge rule; scheduling and object removal belong to the composition owner.

All instants are authoritative UTC. No appointment is created here. No amounts are changed or financial authority granted. Retained transaction, custody, payout and dispute references remain with their source domains. A hold never cancels an active commitment. The local durable store is an isolated module implementation; production storage/dispatch integration and all connected nine-domain proofs remain owed.
