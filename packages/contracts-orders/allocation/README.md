# Orders allocation V1

One physical `watch_id` across all commercial sources; Catalog must reuse this immutable identifier when relisting. The database never records the platform as owner.

* `POST /internal/v1/watches/register`: `RegisterWatch` body, catalog service token, `Idempotency-Key`. Register once at publication. Optional strict boolean `is_demo` (default false) is source content provenance, never seeded reservation behavior; Catalog must set it for labeled demo stock. Identical retries return the existing physical-watch revision; conflicting seller/listing/mode cannot overwrite a commitment.
* `GET /v1/watches/{watch_id}/availability` and `/v1/listings/{listing_id}/availability`: public minimal fence projection; no buyer identity, quote or financial data. Watch-detail slots receive a listing id and use the latter to resolve the canonical physical watch. Projection includes the source `is_demo` label so sample content remains labeled during real reservation actions.
* `POST /v1/reservations`: `ReserveWatch`, current buyer Bearer token, `Idempotency-Key`. `expected_revision` is the Orders revision. Response `{id,status,resource_id,request_id,order}`. Exactly one buyer wins; domain denial `{id,status:'denied',code}` has no payment authority. HTTP 503 on unavailable prerequisite means NOT confirmed: retry the SAME key, never fabricate success.
* `POST /internal/v1/watches/{watch_id}/fences`: auction service token, `FenceWatch`, idempotency. Only the registered auction mode can fence. Unknown/unavailable never means permission to sell. Idempotent same-source fence succeeds; competing sources fail. Fixed-price reservation is not permitted for an auction watch in Sprint 1.
* `GET /internal/v1/watches/{watch_id}/fence?source_id={id}`: authenticated Catalog/Auction read, minimal projection plus `source_matches`. Unknown and unavailable are never sale authority. `GET /internal/v1/operations/{id}` scopes durable command reconciliation to that same calling service.
* `GET /v1/operations/{id}`: owner-private durable command outcome. `GET /v1/orders` and `/v1/orders/{id}`: buyer/seller or scoped `orders.read` principal only.
* `GET /v1/me/reservations?limit=100&cursor={uuid}`: canonical buyer-only L06/L07 workspace source. Returns `{items:[{reservation_id,listing_id,buyer_id,state,total_minor,currency,revision,expires_at,is_demo}],next_cursor:null|uuid}`. Notification-pending USD orders have `expires_at:null`; notified awaiting-payment or payment-unknown records appear while their window remains open. Seller participation never leaks another buyer's reservation. Limit 1–100, owner-scoped UUID keyset cursor. Holds/expiry remain in `/v1/orders`, never projected as paid or payment-ready. `reservation_id` is the same sole Orders order id, not another allocation engine.
* `POST /v1/orders/{id}/transitions`: scoped `orders.manage`, revision + reason. Only the safety hold `payment_unknown` is allowed by this generic command. Paid/released/completed/cancelled commands deny. Simulated checkout is a separate exact signed-payment module; this generic route never grants payment or payout authority.
* `POST /v1/orders/{id}/intake`: scoped `orders.intake`, `CustodyFact`. Pre-release physical fact, NOT final handover. Actor/time/location/actual watch/accessories/condition recorded privately. Returned `resource_id` is the actual custody receipt id.
* `GET /v1/custody/receipts/{receipt_id}`: minimal `CustodyReceipt` for L09 technical-intake verification. Current membership in the receipt's official business plus scoped `orders.intake`, `intake.read` or `intake.write` is required; Identity reselects that authoritative resource organization. Returns `id,order_id,organization_id,received_at,revision,valid:true` only for the latest actual recorded fact. A later custody fact fences older receipts with 409. No sample receipt, private watch details, paid/checked release or inspection pass is implied. No public gateway route exposes this proof.

Fresh Identity `/internal/v1/principal` is required for every private call. Internal register/fence require RS256 service claims (`type=service`, issuer `BT_AUTH_ISSUER`, exact audience `orders`, subject `catalog`/`auction`) verified with `BT_SERVICE_AUTH_PUBLIC_KEY`. There is no public gateway registration for internal endpoints.

Released Pricing Orders validation V1: `GET /internal/v1/quotes/{id}/validation` with buyer bearer token, exact `ValidatedQuote` response in `__init__.py`. All IDs, listing revision, owner, exact integer amount, status and UTC expiry are revalidated. Missing or malformed upstream stays unavailable. Consumer fixtures are tests only, never runtime fallbacks.

Accepted economics never expire with the preview. New USD orders start `awaiting_notification` with null `notified_at` and deadline. Only authenticated Communications receipt `POST /internal/v3/payment-notices` (`v3.py`) binds the original event, buyer, order and durable notice plus verified simulated delivery. Duplicate receipt starts once; conflicting receipt is refused. Missing legacy notice intents are recovered transactionally without manufacturing delivery or a running clock.

The original notice starts card's 24 hours or Whish/OMT's 48 hours; before route selection allow 48 hours. Switching never restarts the clock. One valid initiated attempt extends its route deadline by 24 hours once. At/equal after deadline a new attempt is refused. Expiry locks order, attempts and watch: no attempts or only final declines releases once to `expired_released`; pending/unknown retains `expired_fenced` for support. No automatic relisting or runner-up. Committed historical non-USD orders stay unchanged for restricted reconciliation, excluded from active customer totals and forms.

New winner/offer allocations consume Pricing v3 current committed authorization and exact retained financial DTO. No new auction purchase is accepted; an old identical operation can still reconcile. `/v1/orders/{id}/checkout` returns original notification, extension and server-calculated route deadlines, never a client-invented price clock. `/internal/v2/orders/{id}/paid-fact` exposes versioned notified state and typed retained economics; v1 keeps its exact prior shape only for representable states and otherwise returns `contract_upgrade_required`.

Events `orders.watch-registered.v1`, `orders.reserved.v1`, `orders.fenced.v1`, `orders.state-changed.v1`, `orders.intake-recorded.v1` enqueue minimal resource/revision identifiers transactionally. Reservation also atomically appends released Communications `orders.reservation-created.v1`: exact occurrence/recipient/resource/owner/revision/time, `kind:reservation_ready`, required and source sample marker. It contains neither payment authority nor private custody/quote evidence. The Communications destination adapts only the fixed receiver path to `/internal/v1/inbox/events`, preserving the same bounded client and authenticated lease retry. The separate required `orders.payment-action-required.v3` intent is not a receipt or payment authority; its subscribed durable buyer-notice receipt alone starts payment time. Reference-only event types are not registered notices and remain pending until their destination owner releases a handler. Missing service credentials likewise leave durable work pending, never mark it delivered.
