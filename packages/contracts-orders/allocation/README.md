# Orders allocation V1

One physical `watch_id` across all commercial sources; Catalog must reuse this immutable identifier when relisting. The database never records the platform as owner.

* `POST /internal/v1/watches/register`: `RegisterWatch` body, catalog service token, `Idempotency-Key`. Register once at publication. Optional strict boolean `is_demo` (default false) is source content provenance, never seeded reservation behavior; Catalog must set it for labeled demo stock. Identical retries return the existing physical-watch revision; conflicting seller/listing/mode cannot overwrite a commitment.
* `GET /v1/watches/{watch_id}/availability` and `/v1/listings/{listing_id}/availability`: public minimal fence projection; no buyer identity, quote or financial data. Watch-detail slots receive a listing id and use the latter to resolve the canonical physical watch. Projection includes the source `is_demo` label so sample content remains labeled during real reservation actions.
* `POST /v1/reservations`: `ReserveWatch`, current buyer Bearer token, `Idempotency-Key`. `expected_revision` is the Orders revision. Response `{id,status,resource_id,request_id,order}`. Exactly one buyer wins; domain denial `{id,status:'denied',code}` has no payment authority. HTTP 503 on unavailable prerequisite means NOT confirmed: retry the SAME key, never fabricate success.
* `POST /internal/v1/watches/{watch_id}/fences`: auction service token, `FenceWatch`, idempotency. Only the registered auction mode can fence. Unknown/unavailable never means permission to sell. Idempotent same-source fence succeeds; competing sources fail. Fixed-price reservation is not permitted for an auction watch in Sprint 1.
* `GET /internal/v1/watches/{watch_id}/fence?source_id={id}`: authenticated Catalog/Auction read, minimal projection plus `source_matches`. Unknown and unavailable are never sale authority. `GET /internal/v1/operations/{id}` scopes durable command reconciliation to that same calling service.
* `GET /v1/operations/{id}`: owner-private durable command outcome. `GET /v1/orders` and `/v1/orders/{id}`: buyer/seller or scoped `orders.read` principal only.
* `GET /v1/me/reservations?limit=100&cursor={uuid}`: canonical buyer-only L06/L07 workspace source. Returns `{items:[{reservation_id,listing_id,buyer_id,state:'awaiting_payment',total_minor,currency,revision,expires_at,is_demo}],next_cursor:null|uuid}`. Only current buyer's unexpired awaiting-payment records appear; seller participation never leaks another buyer's reservation. Limit 1–100, owner-scoped UUID keyset cursor. Holds/expiry remain in `/v1/orders`, never projected as paid or payment-ready. `reservation_id` is the same sole Orders order id, not another allocation engine.
* `POST /v1/orders/{id}/transitions`: scoped `orders.manage`, revision + reason. Only safety hold `payment_unknown` is released in Sprint 1. Paid/released/completed/cancelled commands deny; no charge or payout endpoint.
* `POST /v1/orders/{id}/intake`: scoped `orders.intake`, `CustodyFact`. Pre-release physical fact, NOT final handover. Actor/time/location/actual watch/accessories/condition recorded privately. Returned `resource_id` is the actual custody receipt id.
* `GET /v1/custody/receipts/{receipt_id}`: minimal `CustodyReceipt` for L09 technical-intake verification. Current membership in the receipt's official business plus scoped `orders.intake`, `intake.read` or `intake.write` is required; Identity reselects that authoritative resource organization. Returns `id,order_id,organization_id,received_at,revision,valid:true` only for the latest actual recorded fact. A later custody fact fences older receipts with 409. No sample receipt, private watch details, paid/checked release or inspection pass is implied. No public gateway route exposes this proof.

Fresh Identity `/internal/v1/principal` is required for every private call. Internal register/fence require RS256 service claims (`type=service`, issuer `BT_AUTH_ISSUER`, exact audience `orders`, subject `catalog`/`auction`) verified with `BT_SERVICE_AUTH_PUBLIC_KEY`. There is no public gateway registration for internal endpoints.

Pricing adapter provisional V1: `GET /internal/v1/quotes/{id}/validation` with buyer bearer token, exact `ValidatedQuote` response in `__init__.py`. All IDs, listing revision, owner, exact integer amount, status and UTC expiry are revalidated. Missing or malformed upstream stays unavailable. Consumer fixtures are tests only, never runtime fallbacks.

Deadline: min(quote expiry, server UTC now + configured unpaid fixed-price TTL, default 900s). Equal/after deadline cannot authorize payment. Expiry is its own audited transition to `expired_fenced`: the physical fence is retained until future financial reconciliation. There is deliberately no automatic reallocation or unsafe unlock in Sprint 1.

Events `orders.watch-registered.v1`, `orders.reserved.v1`, `orders.fenced.v1`, `orders.state-changed.v1`, `orders.intake-recorded.v1` enqueue minimal resource/revision identifiers transactionally. Destination delivery uses foundation authenticated outbox leases. Missing service credentials leave durable work pending, never mark it delivered. No private notes or custody evidence is sent.
