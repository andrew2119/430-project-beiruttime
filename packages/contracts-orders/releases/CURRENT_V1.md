# Orders release v1

Private boundary: orders.releases.v1. Amounts are integer USD cents; displays use dollars. All results are simulated. No public event, log or preview contains evidence references, recipient account details or private proof. A preview is private and never execution permission.

Operations: GET /v1/releases/{order_id} reads current conditions; POST /v1/releases requests one release; GET /v1/releases/operations/{operation_id} retrieves the durable result; POST /v1/releases/operations/{operation_id}/recover reconciles the same transfer. Authentication supplies actor and selected organization; a command cannot impersonate either. Unknown references return denied to avoid disclosing another record. Reads, duplicates and recovery recheck current identity, membership, record permission and assignment. Body size is at most 8192 bytes. Calls have a four-second deadline and no automatic new-operation retry.

The one Orders journal implements ReleaseJournal in the release module. Its reserve transaction locks the canonical order, current source revisions, hold fence and journal operation. It checks current authority and immutable command equality before replay. It invokes the supplied decision on the locked authoritative snapshot and server UTC time. A changed source revision denies. Unknown hold or dependency never permits reservation. The same transaction stores the decision, immutable recipient version, principal reservation, fee allocation and one stable transfer outbox row. Unique order and operation constraints prevent a second allocation. This module owns neither balances nor a second journal. The runtime steward supplies the implementation and registration; an absent implementation is unavailable.

A hold committed before reservation wins. A hold racing an already reserved transfer must record an explicit durable investigation/reconciliation outcome under the same fence; it cannot silently clear or redirect a transfer. Dispatch uses the frozen recipient and stable operation as its sole transfer key. A newly verified recipient cannot alter a pending transfer. Failure and lost response keep principal reserved. Recovery looks up/reconciles that transfer and never allocates again. Confirmed transfer, fee collection and the private completion outbox/inbox receipt commit atomically in the journal; a receivable alone is not collected cash. Duplicate callbacks have one durable receipt and conflicting callbacks deny. No fee is refunded by this interface. Refund reservations and confirmed refunds exclude release of the same principal.

The journal must use the same decision function during reservation, not rely on an earlier preview. Paid hold, actual receipt and current inspection/assurance/quality are authoritative source facts with operation/revision bindings. Private watches require actual expert custody and current independent pass. Business watches require current business assurance. Jobs require actual quality tests, fit and returned-parts checks, with three distinct assigned people. Receipt names this watch revision and the authorized buyer recipient; dispatch is insufficient. The entire accepted dispute window is retained, cannot be shortened below 72 hours for private watches or 168 hours otherwise, and starts at actual receipt. Equality is expired. Retained commission or job fee is deducted exactly once; aliases are never summed or recalculated. A legacy currency case is unavailable for release until reconciliation.

v1.py defines immutable schemas. fixtures.json contains synthetic development examples, including denied, stale and lost-response cases; these are not producer proof. Operation envelopes bind actor, organization, order, watch, retained quote/policy, expected source revision and immutable recipient version. An acknowledged operation remains retrievable after restart. Pending is not paid out. On response loss the client keeps the same operation reference. Unknown lookup remains pending/unavailable, never a new transfer.

Every durable result carries the assigned responsible operator and assignment revision, the next action and a follow-up due within 24 hours. A provisional response-unknown envelope may omit the assignment because it cannot invent journal facts; lookup supplies the canonical assignment. Pending investigations retain the responsible operator and escalate after 48 hours without progress.
