# Custody v1

This additive boundary records physical custody, not balances or payment authority.
Runtime registration belongs to the Orders composition owner.

## Operations

Authenticated internal callers use `POST /internal/v1/custody/commands` and
`GET /internal/v1/custody/{order_id}/operations/{operation_id}`. Private delivery
reads use `GET /v1/custody/{order_id}` for exactly one order. Buyer acknowledgement
uses `POST /v1/custody/{order_id}/buyer-receipts` and accepts only buyer_receipt.
No endpoint is registered by this module alone.
`GET /v1/custody/{order_id}/history?offset=0&limit=25` returns immutable operation
summaries in descending revision order, a true server total and bounded paging
(limit 1–100, offset 0–1000000). Proof details are excluded from this timeline.

Commands bind schema_version, operation_id, subject_id (order), watch_id, actor_id,
organization_id, expected_revision, watch_revision, source_revision, quote_id, quote_revision and
policy_revision. Identifiers are opaque 1–100 character references. One stable
operation reference survives timeout and retry; a conflicting body is denied.
The server derives actor and organization from authenticated context, never from
unverified request fields. Private lookup rechecks current access even for retries.

Actions: prepare, dispatch, ready, expert_receipt, job_intake, buyer_receipt, return_receipt,
incident, miss_pickup, resolve_incident. Expert and buyer receipts require actual physical proof;
dispatch never creates receipt. An incident remains held until a separately
authorized incident resolution is supplied by the current provider. No local
command clears a hold. Failed private returns need confirmed seller collection
of the retained 5% commission and disclosed trip, plus a custody instruction.
Unknown/declined collection never permits a return. No collection is initiated here.

## Current source boundary

The injected provider's `current(context, order_id, timeout_seconds=2)` context
returns immutable Facts and preserves their current permission, assignment,
watch, source, quote, policy, payment and inspection/quality bindings until the
local write commits. It must deny revoked/cross-account access, use bounded
dependency calls and serialize invalidation against writes. A cache is insufficient.
An unavailable provider produces unavailable, never a successful receipt.
Production integration must supply this boundary before enabling commands.

Facts include the current exact watch/accessories, agreed address, actual
custodian, seller route, authorized recipients, paid held state, retained USD
amounts, independent assigned expert and physical receipt reference, current
inspection result, business assurance or current job quality. Job quality must
bind scope/work and distinct assessor/approver/reviewer; private inspection must
bind expert receipt, assignment and watch revision. Only the owning providers
may assert these current booleans. For failed return, confirmed collection must
bind the same order, seller, commission, trip and stable collection operation.

Proof has watch_id, recipient, condition, accessories, location, address,
received_at and signed_handoff. Source is buyer_acknowledgement or approved_proof;
the latter needs current provider approval of the exact operation and proof.
Approval binds `approved_proof_operation` and `approved_proof_digest`: the digest
is SHA-256 of UTF-8 JSON with sorted keys, no spacing and unescaped Unicode.
Private evidence bytes/references never enter the public outbox or logs.
UTC timestamps must be aware, not future-dated. Appointments, if added, require
Asia/Beirut civil-time confirmation; UTC receipt is not a civil appointment.

## Outcomes

Success increments revision and atomically stores the operation receipt, private
record and minimal versioned outbox event. Acknowledged records survive restart.
Denied and stale change nothing; unavailable retains the same operation for retry.
Lookup returns the original accepted result, even after a lost response, but only
with current authority. Wrong watch, recipient, accessories, condition, loss,
damage, non-shipment and missed pickup create a hold with responsible operator,
next action and 24-hour follow-up. Missed pickup remains ready for collection.
The previous custodian remains responsible until a valid signed receipt.

Actual buyer receipt snapshots the accepted policy: private 72 hours; business
and jobs 168 hours. At equality the window has expired. Receipt does not release
funds. Current release eligibility remains the responsibility of the one journal.
No sample starts with a pass, payment, receipt, completion or payout.

Job intake requires current assigned staff permission in `job_organization_id`
and approved actual proof naming `intake_recipient`. It records job_received,
without quality approval or a buyer receipt/window. Final handback requires the
same current `job_intake_receipt_id` plus current quality and three distinct
assessor/approver/quality identities. Current inspection and assignment revisions
are retained on private handover; confirmed failed-return collection retains its
collection operation and revision.

`paid_held_at` is the authoritative confirmed held-payment instant. Dispatch is
due three calendar days later. Expert receipt retains a decision due two Beirut
business days later (Monday–Friday, preserving local civil time). Ready pickup
retains a 48-hour reminder and seven-calendar-day support-review deadline.
`due_actions` evaluates before/equal/after using server UTC: equality is due.
Overdue states never invent receipt or payout; pickup stays ready. Scheduling
and durable reminder delivery remain with the runtime composition owner.

Held records retain a responsible operator, 24-hour first-response deadline and
48-hour escalation deadline. Loss/damage also creates a simulated declared-watch-
value insurance review with no actual cover claimed. A current independently
authorized incident resolution must match the held incident revision before a
new custody command may progress. Neither these fields nor publication restriction
flags substitute for the current journal or publication permission provider.

Reads return the private record with a `current` binding containing the current
watch/source/quote/policy revisions and authenticated actor/organization. Historic
receipt bindings are retained separately. No current source permission is
inferred from a historical record. A missing record returns null.

The internal resolve_incident action requires current action permission and the
provider-authorized matching incident revision. It clears the custody hold and
restores the pre-incident lifecycle state while retaining receipt, deadline and
incident history. It never releases funds or clears a separate financial hold.
