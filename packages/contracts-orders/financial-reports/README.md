# Financial reports v1

The operation table in `current.v1.json` is the versioned lookup. Runtime composition is separate. The local route boundary accepts only an authenticated principal supplied by the host, never identity fields from a query string. It uses an injected current-authority reader and the immutable Orders feed. Both providers must enforce the two-second deadline supplied to them. No live provider is configured here.

A request binds operation_id, actor_id, organization_id, subject_id (seller or platform), expected_revision, page, page_size, order_id, action and view. A durable receipt retains those bindings. Every lookup checks current authority again; it does not return stored private answers. Unknown outcomes retain the operation reference across retry and process restart. A revision change requires a fresh explicit read with a new reference. Locale is presentation only and is excluded from operation identity.

The feed envelope is `{schema_version, events, high_watermark, checked_at}`. Each event has `{sequence,event_id,order_id,watch_id,seller_id,organization_id,source_revision,quote_id,quote_revision,policy_revision,kind,state,amount_minor,currency,occurred_at,postings}`. Each posting has `{account,minor}`. The producer must authenticate this stream, retain exact economics, emit actual confirmed facts only as confirmed, and publish cumulative checkpoints from its one journal. Pending facts never count as collected money. A fee owed is distinct from collected fees. A pending fact is immutable; its confirmed resolution has the same order and kind, a higher source revision and a new sequence. There is at most one confirmed cumulative snapshot for each order/kind/revision. Confirmed collected snapshots are monotonic; fee_owed is the current outstanding receivable and may decrease on collection. Buyer fees are distinct from seller fees and never deducted from seller net. Feed snapshots for different facts are cumulative, never additive; repeated deliveries cannot increase totals. Refund is principal only; payout is confirmed transfer only. All simulated results are labeled.

A seller net is actual gross minus confirmed principal refunds minus collected seller fees. Fee receivables remain separate. Operator take rate is collected buyer plus seller fees divided by actual gross, expressed as a rational pair, with no invented value for zero gross. Trial balance contains only the authenticated Orders postings and is a projection, never another journal. A checkpoint ahead of local ingestion is pending. A gap, conflict, backwards fact or unbalanced posting is drift. Freshness is inclusive through 60 seconds; later snapshots are pending. Legacy non-USD facts are rejected from active reports and require restricted reconciliation elsewhere.

The fixtures are synthetic contract examples, not proof of connected collection or payout. O07/O08 integration, durable host database adaptation, current identity integration and route registration remain connected acceptance prerequisites. Reports do not invent custody, inspection, dispute expiry or settlement facts.

Detected feed drift is durably latched across retries and restarts. A later empty response cannot erase that finding. Rebuilding a projection from a reconciled authenticated journal is an explicit steward operation outside this read interface; no customer action clears it.

The highest observed producer watermark is durable across restart. A lower later watermark remains pending until the missing sequence is ingested; it cannot restore a ready report.

Every exported monetary row includes an English or Arabic simulated receipt designation, including after the file is downloaded.
