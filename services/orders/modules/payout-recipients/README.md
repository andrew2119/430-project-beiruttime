# Protected synthetic recipients

This additive module has no runtime registration. Store uses a durable private database supplied by the steward; it is a module test implementation, not a second financial journal. Restrict file access and backups to the private service boundary. No public events contain recipient references.

Service requires an authority provider whose lease checks current identity, selected organization membership and record permission and serializes revocation through commit. verify must authenticate a single-use proof bound to the entire immutable Change, actor and current verified contact, including reauthentication, fresh second factor and changed-recipient verification. Both calls have a two-second budget. A timeout rolls back and returns pending; callers resolve the same operation. The provider must not log proof or recipient values. The clock must be authoritative aware UTC. A projection is insufficient.

Only validated Change instances enter the service. Only the internal Orders journal may call bind_transfer after its own current release checks. The transfer identifier and exact immutable recipient version must be retained in that journal's pending operation. This module cannot charge, release, mark paid or alter existing bindings. Current read and operation lookup require the same authority lease as writes.

Connected identity lease/proof consumption, authenticated route registration, service database adapter, atomic journal integration and restart/reconciliation against those producers remain deferred. Local synthetic fixtures are not connected acceptance.
