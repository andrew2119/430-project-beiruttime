# Buyer wrist targets

The additive router requires `pool` and `fit_measurement_authority` on application state. No runtime registration is included here. The authority callable receives the current request, transaction, subject, watch and organization and returns `(actor_uuid, proof)`. Proof has exact string IDs for actor, subject, watch and organization, an integer `source_revision` and `allowed: true`. It must prove the buyer's current record scope and the destination's current supported bracelet-fit capability, watch commitment and relevant retained revisions from authoritative sources. Writes are buyer-only. Reads may also be granted to currently assigned business staff inside the selected organization; the provider must distinguish the request method and prove that record-read permission and assignment. Authorization fencing must survive until commit; a remote cached answer cannot provide it. Missing configuration returns unavailable. Do not bind the synthetic test provider in a running service.

Apply the additive migration before composing the router. Supply a bounded connection pool and dispatch private outbox references with stable operation IDs and durable consumer receipts. The outbox excludes circumference, source and target. No worker is registered by this module; delivery and its restart proof remain with runtime composition. The module does not grant work, quality, custody, payment or release permission.
