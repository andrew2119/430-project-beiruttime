# Private messages

The composition supplies `messages_store = Store(persistent_file)` and an authenticated `messages_authority` with asynchronous `open(actor, organization, kind, subject)`, `listing(actor, organization, cursor, limit)` and `current(actor, organization, thread)` calls. Every call has a two-second deadline. Missing composition returns unavailable. No live delivery is performed.

`open` returns a stable deterministic thread snapshot per listing/order/business record. Snapshot fields match the thread contract, with `members: [{actor_id, organization_id, joined_at, left_at}]` and `authority`. Intervals are UTC, inclusive at entry and exclusive at removal. Rejoining starts a new interval and cannot reveal earlier private messages. Manual aftercare uses a separate business thread with immutable `original_work_id`. The source alone sets `paid_held`, current organization/assignment, source/quote/policy revisions and `active_support`. `current` returns these same record bindings plus actor, actor organization, subject organization (`subject_organization_id`), thread, subject, watch, `current_member` and `state: authorized|denied|unavailable`. It must recheck current identity, business, assignment, commitment and record permissions, rather than trust retained economics. Listing returns authorized snapshots, server total and next cursor. No participant profile email/phone is projected.

Source membership changes must replace the snapshot through `provision` before read admission. Current source revision mismatches deny until refreshed. The provider must serialize snapshot publication with membership changes; historic cached authorization is insufficient. Active custody and assigned support belong in an active-support thread; ordinary block requests cannot sever it. Active support bypasses ordinary blocks while its duties remain current; the retained ordinary blocks apply again when support closes. Private file uploads are not admitted; photo references require a separate current-membership media boundary before attachment support can be enabled.

Receipts retain the authenticated organization, including personal scope. Lookup and retry reject a different organization even when current membership permits the same person to access the thread. Older receipts without a recorded organization binding fail closed without repeating the command.

The service-owned transactional store retains ordered messages, markers, blocks, private reports, delivery fields, operation receipts and a minimal invalidation outbox. Consumers acknowledge each outbox row only after durable publication; a repeated event is deduplicated by its row identifier. Notification delivery must resolve verified recipients and safe authenticated links through the notice owner, with no message previews or contact values. Pending reports and false-positive appeals require independent assigned moderation through the trust owner; no public report/evidence endpoint is exposed. Delivery fields are separate from messages and admitted only against current paid-held facts. They are never included in thread previews or events.

The local store is a durable single-file implementation for module tests and an explicit composition boundary. Production storage selection, module discovery support for this lane, outbox delivery, assigned moderation, private media and connected source/notice/trust integration remain composition work. This module does not register a second shared authority or financial journal.

`composition.json` is an additive descriptor for the composition owner. It is deliberately outside automatic module discovery until that shared boundary admits this lane; an unsupported live manifest would prevent service startup.

A committed block receipt remains recoverable by its original actor and organization after a lost reply, through lookup or an identical retry. Current membership and source authority still apply. Only the recorded block kind receives this exception; private messages and other receipts remain blocked. Older receipts without a recorded kind do not receive the exception.
