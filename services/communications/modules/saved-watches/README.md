# Saved-watch module

`Store` provides transactional private saves, operation receipts, canonical source snapshots and a durable deduplicated outbox. Its embedded database is a local development adapter. Supply one persistent file and a bounded `Providers` implementation; never use a temporary database for acknowledged service changes. Store access is serialized per instance, and write transactions serialize instances sharing the same file. Close on service shutdown. Observe canonical source invalidations and poll due endings even when no public bid changes. Dispatch at most 50 pending rows per invocation; schedule bounded retries using the same notice identifier. Per-row failures do not stop later recipients; least-recently attempted rows progress first. Five failed attempts retain a held outbox row with communications support as next actor, rather than inventing delivery. Support owns explicit reconciliation before any further retry.

`routes.py` derives owner from current authenticated identity and supplies bilingual safe errors. It returns unavailable until the service supplies `app.state.saved_watches`. `composition.json` describes the proposed additive composition; it is deliberately outside automatic module discovery until the shared registry supports this lane. No private projection authorizes a charge, approval, release or exclusive commitment.

The owning service must compose persistent production storage, bounded authenticated identity/source adapters, scheduled observation and the personal inbox receiver described by the published contract. Required outbid delivery belongs to its existing independent path. Production database, connected delivery and runtime composition remain separate acceptance dependencies.

Public snapshot comparison is not an activity source. Implement `occurrences` with the retained complete canonical activity contract; fail unavailable rather than truncate or synthesize events. Its maximum is 200 occurrences per invocation. Larger backlogs require a provider-supported bounded catch-up contract before connected acceptance.

Supply current named recovery and escalation assignments through `recovery_assignment`, plus scoped `authorize_recovery`. Five failed attempts atomically retain the hold and its deadlines. Scheduled dispatch advances overdue response and escalation states even with no deliverable rows. `recovery` reads one authorized record; `reconcile` atomically records an operator response and stable receipt and permits five further attempts. It keeps the original notice, source and save revision bindings. Current subscription and source checks still govern every retry. The owning service must schedule this work and expose its scoped support boundary before connected acceptance.
