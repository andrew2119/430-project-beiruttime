The owned views are ready for that composition; this is not connected acceptance.

The six shared delivery methods have these boundaries:

1. Ready before press: the shared navigation owner must register `/services`. No route-speed result is claimed before that registration and measurement.
2. Data on intent: `reads.ts` publishes the exact safe public questions for the shared intent owner. Private choices and staff reads are open-only and never intent-warmed.
3. Retained answers: shared scoped page memory owns the retained lifetime and access partition. Read keys include purpose/cursor, business or exact option; private keys also bind the access fingerprint.
4. Content during refresh: an existing exact answer stays visible while its refresh is pending or fails. Retained public content grants no command permission. Explicit save still checks current authority and revisions.
5. First-load placeholders: only a missing answer shows the shared loading state. Paging has a server cursor and total; the directory total counts published profiles before current eligibility filtering, as the visible label explains.
6. One arrival: the directory answer uses the shared arrival boundary once per view/access. Keyboard and reduced motion remain shared responsibilities.
