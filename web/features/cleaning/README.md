# Cleaning page delivery contract

The feature-local `delivery-contract.json` declares `/care/cleaning?request=<service-request-reference>` and its mounted request view. The page mounts the same view for assessment requests, explicit acceptance and uncertain-operation recovery. The view uses the canonical PageFrame, PageHeader and shared usePageRead boundary, with the existing root providers and fields. Shared shell adoption and delivery-contract discovery belong to the separate foundation change; connected route mounting remains owed until that change supplies the shared read scope. No local provider or shared registration is added here.

The actual data question is `['cleaning.v1', subject, access]`, under the shared private page scope. It asks the authenticated service request read once per view; freshness is zero because an old answer never grants permission. Warming is `open-only`: private data is not fetched on hover. Kept answers during same-scope refresh belong to the existing shared read cache; access changes remount the form and clear private input and pending references. There is no separate cache/provider or browser persistence. Locale is deliberately absent from form identity, command and read key. No image payload exists.

The six shared speed methods apply through the existing boundary: ready-before-press and intent delivery require host route registration; retained answers and content during refresh use shared reads; first-load-only loading is the shared State; this request form adds no arrival animation. First frame is a translated loading state inside the existing shell, never a fabricated loaded request. Route warming, emitted page-size gates, theme first frame and retained-content behavior require connected measurement; no speed pass is claimed. No newer source behavior is claimed copied beyond the current canonical boundary.

There is one bounded service record and one assessed line, no result list or invented total. Assessment and private evidence are intentionally separate: this page accepts no private files and creates no appointment. Submitted condition remains private text, never a preview or event. Process, limitations, lead time, retained condition, preservation limits, customer amount, business fee and terms remain visible after acceptance. Dollar text uses exact integer-cent conversion and the shared localized formatter.

A timed-out mutation freezes its full body/reference in memory. Retry first looks up that reference, then resends the exact body only if unknown. A definitive denial clears private content; stale actions require refreshing and explicit terms review. Restart reads acknowledged server state; no offline queue claims success. Unknown outcomes must be recovered through the operation endpoint or responsible support before a replacement action.

Opening another request is disabled synchronously while a command is in flight or uncertain. Its mounted form retains the complete command and reference until recovery succeeds or a definitive denial/stale response resolves it. Editing the request reference or submitting the open form cannot replace that form during recovery. Identity/access changes replace the whole private view and clear its in-memory state.
