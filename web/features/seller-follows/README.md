# Following view

The canonical page frame/header, controls and root scope are reused. No private
shell, provider, palette, motion or browser persistence is introduced. Locale is
read in place; only identity/access changes reset the mounted form and operation.

Read keys are `seller-follows.v1 / access fingerprint / page` and
`seller-publications.v1 / access fingerprint / page`. Both use shared read policy,
open-only warming and scope-bound retained answers. Refresh keeps current content;
only first answers show skeletons. No additional entrance is requested. Shared
ready-before-press navigation and data-on-intent require route registration by the
composition owner; private data is never warmed without current scope. The six
speed methods use those same read definitions, held answers, refresh content,
first-answer placeholders and shared arrival ownership. First-frame and size
measurements remain owed; no performance pass is inferred from source.

Shared page-delivery registration and personal sign-in return routing are outside
this module's lease. Connected acceptance, same-document locale switching, actual
390-pixel geometry, keyboard/theme matrix and physical phone review remain owed.

The current shell supplies the shared read scope only for internal routes. The
following route requires its composition owner to extend that same shell scope;
mounting another provider here would split ownership. The delivery registry and
its validator also require owner changes before this route can pass interface
checks. Until both changes land, the route is not ready for connected use.

A denied write, seller lookup or notice destination hides private content and
clears form values and the pending reference. Refresh cannot reveal retained
answers after that denial; a new current access scope must remount the view.

The page entry is withheld until shared composition is available. The composition
owner must extend the existing root read scope to `/following`, admit that route
in the delivery validator and registry, and mount the exported view with its
private read definitions. No second provider is permitted. Route mounting and
connected navigation proof remain deferred.

Denied reads also latch the private view closed, clear entered values and the
pending reference, and suppress retained answers through refresh, unavailable
responses and language changes. Only a new access scope remounts the view.

Each notice offers independent mark-read and clear controls in both languages.
Opening its source has no read/clear side effect. Both commands share the mounted
pending reference and retry handling; language changes retain the exact command.
Clearing removes the notice from the active list after the confirmed refresh and
does not unfollow its seller.
