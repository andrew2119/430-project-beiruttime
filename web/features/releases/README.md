# Payout composition

The payout desk consumes Beirut Time's canonical page composition and controls. Mount ReleaseDesk inside the existing canonical shell/read scope, keyed by the current access fingerprint and selected organization, never by locale. This module supplies no route entry: the shared delivery registry currently accepts only internal routes, and its frozen-page ledger cannot grow. The route steward must extend the shared delivery boundary and register the exact payout route, read scope and first-frame contract before adding its page entry. PayoutsUnavailable supplies the bilingual unavailable view for that composition. The root remains the only provider, main landmark, navigation and notification outlet.

The private read key is orders.releases.v1 plus access fingerprint, selected organization and exact order reference. It is open-only, with zero freshness for financial conditions. The shared read scope clears on access change. A retained answer can remain visible during refresh, but cannot enable release until that refresh succeeds. The server repeats every condition under the hold fence.

The six delivery contracts are: shared route preparation before press; open-only private data on intent; shared scoped retained answers between visits; content during refresh; placeholders on first load only; and one shared answer-arrival fade. Shared route and read registration must bind this definition before preparation or cross-visit retention is offered. The unavailable view needs no private read; route first-frame delivery remains deferred until registration. No local provider, animation table, shell or private cache is introduced. Page size and phone geometry require measurement on the composed route.

The mounted form owns order input, selected order and the immutable pending command in memory. A locale rerender changes copy and digit shapes without changing identity or submitting. Unknown responses preserve the same command. Reopening an order discovers its active operation and reads the durable scoped result before offering recovery. Recovery uses the same operation and cannot change recipient. Current access denial hides private content; access changes clear it. The desk handles one exact order, not a truncated collection. Support remains available from unavailable, denied and pending states.
