# Device notification page

The page uses the canonical page frame, header, state, buttons and root providers. It adds no shell or notification outlet. Language changes preserve the mounted device form and pending request; identity changes replace it and discard private in-memory state. Only the random installation identifier is retained in local storage. Subscription keys and pending command bodies remain in memory.

The actual read is `GET /v1/browser-push/devices/{device_id}`, keyed by `['browser-push.v1', access_fingerprint, device_id]` inside the shared access partition. The read is open-only and immediately stale; intent never requests permission, subscribes or mutates a device. The shared reader keeps an answer during refresh within the same access scope. Identity changes cannot reuse it. Initial rendering uses the canonical loading State; later requests retain available content. There is no feature-local arrival motion or query provider.

Ready-before-press uses the existing shell destination mechanism when its steward registers this route. Data-on-intent is deliberately withheld for this private device read. Retained answers, content during refresh and first-load-only waiting states use the shared reader. Arrival and page-size measurement remain the shared shell's responsibility. Route registration, cold/warm first-frame measurement and emitted page-size acceptance require composition outside this module.

The host registers the notification-devices route with the canonical shell and page registry, mounts the communications route factory, issues its secure device capability, supplies public subscription configuration, and imports `push-events.js` from its existing worker. This feature never registers a root worker. Absent any prerequisite, subscription remains unavailable and the inbox stays reachable. Logout and account switching call the server session-revocation hook before acknowledging the identity transition; page unmount alone is not revocation.

The single-device screen has no collection, total or pagination. No camera, file, password, currency or appointment input is introduced. Bilingual generic system notifications open the inbox; its current record action remains the access-check boundary. Delivery never changes inbox read/clear state or starts a payment clock.

The route entry is supplied as `entry.tsx` for host composition, rather than an unregistered routed page. Its owner must register the delivery contract and mount the entry together; the shared registry currently accepts internal demonstration routes only. No frozen-page exception is added. Installation access failure renders unavailable and the refresh action retries installation before starting the device read. It never replaces a retained pending command.
