# Cancellation workspace

This is a single-record private form composed through PageFrame and PageHeader using the existing shared layout, fields, notices and state components. The feature-local composition boundary supplies compatibility exports until shared page/read exports land. No second shell or provider is mounted. Language is read from the root locale context. Both the form control and the shell language link update the locale URL and cookie, then refresh the same route so the root shell, direction and providers receive the new locale. There is no private language state. The workspace stays at the same tree position and access key. Inputs and exact pending commands remain in memory; an access-fingerprint change clears them. Root refresh retention and shell geometry still require connected verification.

The POST command is immutable once sent. Unavailable responses keep the exact operation for retry; GET resolves it without creating another command. A saved reference can be looked up after restart using its order/watch and scope. Restored lookups cannot submit a reconstructed command. A conclusively denied result allows current details to be reviewed, while displaying the previous reference. Accepted paid outcomes and custody/refund review never display completed cancellation.

## Read and speed contracts

The read is `GET /v1/cancellations/operations/{operation_id}?subject_id=…` with current organization scope. The page has no collection, synthetic totals or pagination. The feature-local usePageRead performs this no-store read; cancellationRead declares its scope and key for shared integration. Its in-memory read identity is the mounted access fingerprint plus immutable subject and operation. The gateway and runtime composition must register this private route before connected use.

- Ready before press: shared controls are available with the page; no speculative cancellation or permission check is treated as authority.
- Data on intent: the explicit operation check performs one bounded authenticated read. Hover/focus warming is absent.
- Kept answers: the last outcome stays mounted during a refresh. There is no persistent or cross-visit private query cache.
- Content during refresh: the prior outcome and reference remain visible; the check button is disabled while active.
- First-load placeholders: session restoration uses the shared loading rows. Operation loading uses the same mounted form and translated busy button; no invented initial success appears.
- Arrival and size: the shared shell owns motion. There is no feature animation or independently measured page-size gate. Newer warming and size improvements remain integration gaps.

The module does not publish a registration, extra provider, palette or shell. Current unavailable access, errors, declined decisions, pending payment/return and accepted states have English and Arabic copy. The shared shell’s direction and actual phone geometry must be verified in the separate viewport matrix before claiming complete phone behavior.

An uncertain delivery retains its immutable operation even when a later retry is denied. Restored access retries the same command; only a conclusive result or an initial definitive rejection permits correction. The localized support link opens the existing inbox with only the operation reference, excluding the reason and other private form details. Connected support handling remains owed.
