# Request and intake views

The business intake page supplies a localized document title and opens the
assigned-record editor. The service enforces current assignments during
preparatory intake and fails closed during provider outages.
Preparatory save and same-reference recovery are exercised locally with
contract-matching providers. Connected acceptance requires current assignment,
custody and opening providers, runtime photo processing and foundation adoption
of the feature declarations.

Intake requires current assignment authority for records, evidence and recovery.
Until the shell provides the shared private read scope, the adapter runs the
same read definitions inside the mounted editor. Receipt lookup and closure use
the existing records POST route. A recovered receipt must match the original
operation, order and expected result revision.

Preparatory intake records symptoms before receipt or payment.
Canonical fields and page composition share the root providers. Language
changes in place. Identity and business changes clear private view ownership.
Uncertain writes retain their operation references. Drafts and files stay in memory.


The request view reads current watch and eligible destination context, submits symptoms, modifications, limited assessment permission and private photos through the versioned transport. It reports unavailable while provider composition is absent. A lost response retries the same operation and acknowledged uploads. Choosing an assessment is never a booking or received state. No demonstration success is supplied.
