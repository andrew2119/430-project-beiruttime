# External account view

The additive page view uses the canonical header, frame, controls and state composition. It has no additional shell or provider. The caller supplies the current access partition and private operation. Changing that partition clears the mounted private state; changing locale keeps the same controller and operation. No credential, proof or provider callback enters browser persistence or a page read cache.

The only read is the explicit operation lookup supplied by the identity composition boundary. Its private read key is the access partition plus operation reference and expected revision. No speculative warming or prefetch is permitted for a sign-in command. The six shared speed methods apply as follows: shared shell readiness; no private data on intent; no retained private answers across access changes; current operation stays visible during refresh; only the first unresolved identity load uses a shared placeholder; shared page arrival only, with no feature motion. The first frame is the honest unavailable state until composition supplies current data. No latency or bundle-size pass is claimed.

`page-view.tsx` is the owned route composition leaf. It is deliberately not a registered route: the shared page registry and session/provider wiring are outside this lease. The steward must register `/account/external` and provide the authoritative access partition and transport before the journey is connected. Retry looks up the exact operation; a pending callback that has not reached identity completion still requires the original callback command retained in memory by the provider boundary. It must never synthesize a successful result or a second action reference.

The view contains no list, money, appointment, password or file input. Pagination and private-file storage do not apply. EN/AR text and uncertain/denied/stale/unavailable recovery are complete. Actual theme, keyboard, mixed-script overflow, 390×844 geometry, screenshots and physical-phone checks remain acceptance requirements.
