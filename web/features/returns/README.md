# Returns page

The view uses the existing root locale/theme provider and canonical page and field
components. It deliberately shows unavailable until the runtime steward supplies
the authenticated return adapter. It never invents permission or success.

The mounted form retains order, reason and exact pending reference across in-place
locale updates. Access changes clear private state and discard late responses.
There are no private files, browser persistence, list totals or page collections.
A bounded request retries the same immutable command after a lost response.
The adapter must resolve current order/watch/source/policy bindings server-side;
entered references confer no authority.

Page data/read key: none until authenticated composition exists. No private answer
is warmed or retained across visits. Route warming remains with the shared shell;
no alternate provider or speculative private prefetch is installed. Content stays
visible while retrying, placeholders are not replayed, and no arrival motion is
added. First frame is an honest unavailable state. Emitted-size measurement and
all six shared speed runtime proofs remain deferred to route composition.


Composition contract: view `web/features/returns/returns.tsx` is a private,
unavailable-first form with no composed data read. No route entry is published.
The runtime owner must register the private route and compose its authenticated
adapter together before publishing `/returns`. Route delivery and connected
acceptance remain deferred; the isolated view is not a delivered page.
Current and command answers must name the requested subject. Changing the order
clears its prior answer and revision; locale changes preserve the same order,
draft and pending operation. Uncertain command responses retain that operation.
