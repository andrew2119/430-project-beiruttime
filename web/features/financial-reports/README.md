# Receipts composition

`Receipts` consumes the host's current selected `ReportScope` and reload action. Mount the owned receipt entry inside the one canonical shell and shared read provider. The additive entry is intentionally not a registered page: the route registry and shell migration are outside this module's ownership. No secondary provider or shell is mounted here.

The data key is `financial-reports.v1`, access fingerprint and the complete stable read request. A request reference survives retries and in-place locale changes. A matching request reuses its reference on return visits through a bounded memory-only identity registry, allowing the shared cache to retain answers. New page, selection, scope or revision bindings create a fresh reference. The registry holds at most 1,000 request identities and clears on access change. Shared cache eviction ends answer retention; it does not claim a previously checked answer is current. An access change removes the private subtree. Language is not a component key, query key or submission trigger. Every request uses current authenticated access and no browser persistence.

The six shared speed methods apply as follows: ready-before-press uses canonical control code; data-on-intent is explicitly open-only for private reads; answers are held by the shared access-partitioned memory; current answers remain during same-request refresh with print/export blocked; skeletons appear only without a first answer; no extra arrival animation is added to this repeated financial read. Shared route warming and measured size gates require the steward's route registration. First frame has the canonical header and either the current access state or first-answer skeleton. No unmeasured speed claim is made.

The transport host maps authenticated requests to the published internal operation lookup and streams the bounded CSV response through its cookie-authenticated export route. It must never cache private exports or put response contents in diagnostics. A fresh permission check is required even for a previously loaded receipt. The export reference is stable across a retry and locale changes. Printing is an explicit action, includes simulated labels and does not mutate money.

Printing revalidates the exact current read reference before displaying the fresh answer in the print surface. Access changes synchronously abort and fence that check; denied, stale, pending and unavailable answers cannot print.
